## 摘要
具身智能体越来越多地依赖大语言模型（LLM）进行规划，但每步调用 LLM 会带来严重的延迟和成本。在本文中，我们展示了具身任务表现出极强的规划局部性，即下一步规划在很大程度上可以根据当前规划进行预测。基于此，我们引入了 AgenticCache，这是一个通过重用缓存规划来避免每步调用 LLM 的规划框架。在 AgenticCache 中，每个智能体查询频繁规划转换的运行时缓存，而后台缓存更新器则异步调用 LLM 以验证和优化缓存条目。在四个多智能体具身基准测试中，AgenticCache 在 12 种配置（4 个基准测试 x 3 个模型）下平均将任务成功率提高了 22%，模拟延迟降低了 65%，Token 使用量降低了 50%。因此，基于缓存的规划重用为实现低延迟、低成本的具身智能体提供了一条切实可行的路径。代码可在 https://github.com/hojoonleokim/MLSys26_AgenticCache 获取。

## Abstract
Embodied AI agents increasingly rely on large language models (LLMs) for planning, yet per-step LLM calls impose severe latency and cost. In this paper, we show that embodied tasks exhibit strong plan locality, where the next plan is largely predictable from the current one. Building on this, we introduce AgenticCache, a planning framework that reuses cached plans to avoid per-step LLM calls. In AgenticCache, each agent queries a runtime cache of frequent plan transitions, while a background Cache Updater asynchronously calls the LLM to validate and refine cached entries. Across four multi-agent embodied benchmarks, AgenticCache improves task success rate by 22% on average across 12 configurations (4 benchmarks x 3 models), reduces simulation latency by 65%, and lowers token usage by 50%. Cache-based plan reuse thus offers a practical path to low-latency, low-cost embodied agents. Code is available at https://github.com/hojoonleokim/MLSys26_AgenticCache.

#### 1. 核心问题与研究动机
具身智能体（Embodied AI）通常采用“感知-规划-行动”循环，现代方法倾向于使用大语言模型（LLM）作为推理核心。然而，**每步调用 LLM 会产生巨大的推理延迟和经济成本**，导致智能体在执行任务时频繁停顿，难以满足实时性需求。
论文观察到具身任务具有**规划局部性（Plan Locality）**：即智能体的下一步规划往往可以从当前规划和局部上下文中预测（例如“抓取”后通常接“运输”）。受计算机体系结构中分支预测和缓存机制的启发，作者提出了 AgenticCache，旨在通过重用缓存的规划转换来减少对 LLM 的同步依赖。

#### 2. 方法论
AgenticCache 的核心是一个**运行时缓存**与**后台异步更新器**相结合的混合规划框架：
*   **缓存结构（2-Gram Pattern）**：缓存存储规划转换对 $\langle P_i \to P_j \rangle$。每个条目包含任务状态元数据（如步数、持有物品数、完成进度等）的取值范围。
*   **评分与选择机制**：智能体查询缓存时，通过元数据过滤可行候选集，并根据复合得分 $S = C \times I$ 选择下一步。其中 $C$ 是局部转换频率（Count），$I$ 是全局重要性因子（Importance，由 LLM 确认的比例决定）。
*   **异步更新器（Cache Updater）**：
    *   **验证与修正**：在后台异步调用 LLM。如果 LLM 建议与缓存一致，则增加该条目的置信度；如果不一致，则立即替换当前执行的规划（Plan Replacement）并更新缓存。
    *   **查询抑制**：当 LLM 与缓存达成一致或正在执行修正规划时，抑制冗余的 LLM 查询以节省 Token。
*   **冷启动优化**：支持通过少量离线成功轨迹进行“预填（Prefilling）”，使智能体在任务开始时即可利用先验知识。

#### 7. 优点
*   **架构创新**：将计算机体系结构中的缓存思想成功引入具身智能领域，利用“规划局部性”打破了 LLM 推理的串行瓶颈。
*   **异步修正机制**：不同于简单的缓存重用，其异步更新和即时替换机制保证了智能体在环境变化时的灵活性。
*   **实用性强**：显著降低了使用昂贵 LLM（如 GPT-5）的经济门槛，且与现有的 LLM 服务优化技术（如 KV Cache）完全兼容。

#### 8. 不足与局限
*   **多智能体冲突**：在极高协同要求的场景下，缓存重用可能导致智能体间的动作不一致（如两人同时抢占同一资源），虽然更新器最终会修正，但存在短暂的延迟。
*   **局部性依赖**：该方法依赖于任务的结构化程度。在完全开放、无规律的探索任务中，规划局部性可能变弱，导致缓存命中率下降。
*   **元数据依赖**：缓存过滤依赖于手动选择的元数据字段（如步数、物品数），对于不同环境可能需要一定的工程调整。
