## 摘要
我们提出了 JigsawRL，这是一个高性价比的框架，它探索了流水线复用（Pipeline Multiplexing）作为强化学习（RL）并行性的一个新维度。JigsawRL 将每个流水线分解为子阶段图（Sub-Stage Graph），从而揭示了被阶段级系统所掩盖的阶段内和工作节点间的不平衡。在此抽象基础上，JigsawRL 通过动态资源分配解决了复用干扰，通过在工作节点间迁移长尾 rollout 消除了碎片化利用，并将它们的协调建模为一个通过前瞻启发式算法解决的图调度问题。在 4-64 块 H100/A100 GPU 上，针对不同的智能体 RL 流水线和模型，JigsawRL 在同步 RL 上比 Verl 实现了高达 1.85 倍的吞吐量，在异步 RL 上比 StreamRL 和 AReaL 实现了 1.54 倍的吞吐量，并支持具有适度延迟权衡的异构流水线。

## Abstract
We present JigsawRL, a cost-efficient framework that explores Pipeline Multiplexing as a new dimension of RL parallelism. JigsawRL decomposes each pipeline into a Sub-Stage Graph that exposes the intra-stage and inter-worker imbalance hidden by stage-level systems. On this abstraction, JigsawRL resolves multiplexing interference through dynamic resource allocation, eliminates fragmented utilization by migrating long-tail rollouts across workers, and formulates their coordination as a graph scheduling problem solved with a look-ahead heuristic. On 4-64 H100/A100 GPUs across different agentic RL pipelines and models, JigsawRL achieves up to 1.85x throughput over Verl on synchronous RL, 1.54x over StreamRL and AReaL on asynchronous RL, and supports heterogeneous pipelines with moderate latency trade-off.

#### 1. 核心问题与研究动机
随着大语言模型（LLM）后训练（Post-Training）需求的激增，强化学习（RL）已成为模型对齐和能力增强的标准技术。然而，现有的 RL 框架（如 Verl, OpenRLHF）主要关注时间效率，而忽视了**成本效率**。
*   **研究动机**：作者通过分析发现，现有系统的 GPU 利用率（MFU）通常低于 10%。这主要是由于 Rollout（采样）阶段的**负载不均衡**导致的：长尾序列、多轮对话和外部工具调用使得大量 GPU 资源在等待少数慢样本时处于闲置状态。
*   **核心问题**：如何在保证训练稳定性的前提下，通过利用不同 RL 任务之间的资源互补性，提升硬件利用率并降低训练成本？

#### 2. 方法论
JigsawRL 提出了“**流水线复用（Pipeline Multiplexing）**”作为 RL 并行性的新维度，其核心技术包括：
*   **子阶段图抽象（Sub-Stage Graph）**：将粗粒度的阶段（Rollout, Training, Reference）分解为细粒度的子阶段。例如，将 Rollout 根据 Token 数量划分为不同的计算密集度桶（Buckets），从而暴露阶段内和工作节点（Worker）间的不平衡。
*   **子阶段复用（Sub-Stage Multiplexing）**：利用不同子阶段对计算（SM）和显存（Memory）需求的互补性。例如，将显存受限的“长尾解码”与计算密集型的“模型训练”在同一 GPU 上空间复用。通过 NVIDIA MPS 或 Green Context 实现动态 SM 分配。
*   **子阶段合并与迁移（Sub-Stage Merging & Migration）**：针对数据并行（DP）节点间的不平衡，JigsawRL 会动态地将长尾 Rollout 样本迁移到少数节点上进行聚合处理，释放其他节点的资源以供其他流水线使用。
*   **前瞻性调度（Look-ahead Scheduling）**：采用启发式算法，在调度窗口内模拟多种复用和合并组合，选择能够最小化关键路径延迟的执行方案。

*   **充分性评价**：实验设计非常充分且客观。作者不仅对比了吞吐量，还诚实地报告了复用带来的单流水线延迟增加（Latency Trade-off），并验证了在异构模型（不同大小模型混合训练）下的有效性。

#### 6. 主要结论与发现
*   **吞吐量提升**：相比同步基准 Verl，JigsawRL 实现了高达 **1.85 倍** 的吞吐量提升；相比异步基准 StreamRL/AReaL，提升达 **1.54 倍**。
*   **成本效率**：在相同的硬件预算下，JigsawRL 显著降低了每百万 Token 的美元成本，且随着 GPU 规模扩大，其优势更加明显。
*   **资源利用**：通过空间复用，GPU 的平均 MFU 得到了显著提升，证明了“流水线复用”是解决 RL 训练低效问题的有效途径。

#### 7. 优点
*   **创新维度**：跳出了单流水线优化的局限，提出了多流水线空间复用的新思路。
*   **精细化控制**：子阶段图的抽象比传统的阶段级调度更贴合 RL 任务的动态特性。
*   **兼容性强**：能够支持同步和异步 RL 算法，并能处理异构模型和复杂的智能体工作负载（如工具调用）。
*   **实用性高**：针对云端共享集群或 Serverless 环境，这种多任务复用技术具有极大的商业价值。

#### 8. 不足与局限
*   **延迟权衡**：虽然总吞吐量增加，但单个任务的完成时间（Per-step Latency）会有所增加（约 1.14x-1.48x），对于实时性要求极高的场景可能不适用。
*   **显存压力**：空间复用对显存管理要求极高，在模型极大（如 70B+）且 GPU 显存有限的情况下，复用的空间会被压缩。
*   **模型覆盖**：目前主要针对稠密模型（Dense Models），尚未深入探讨在混合专家模型（MoE）上的表现（尽管作者提到 MoE 提供了更多复用机会）。
