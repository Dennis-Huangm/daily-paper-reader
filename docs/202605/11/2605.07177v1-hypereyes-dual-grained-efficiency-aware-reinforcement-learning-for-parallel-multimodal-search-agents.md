## 摘要
现有的多模态搜索智能体按顺序处理目标实体，每个实体发出一次工具调用，每当查询分解为独立的子检索时，就会累积冗余的交互轮次。我们认为，有效的多模态智能体应该搜索得更广而非更长：即在单轮内并发调度多个定位查询。为此，我们提出了 HyperEyes，这是一种并行多模态搜索智能体，它将视觉定位与检索融合为单个原子操作，在实现跨多个实体并发搜索的同时，将推理效率视为首要训练目标。HyperEyes 的训练分为两个阶段。在冷启动监督阶段，我们开发了一个适用于并行的多模态数据合成流水线，涵盖视觉多实体和文本多约束查询，并通过渐进式拒绝采样策划面向效率的轨迹。在此基础上，我们的核心贡献——双粒度效率感知强化学习框架，在两个层面上运行。在宏观层面，我们提出了 TRACE（工具使用参考自适应成本效率），这是一种轨迹级奖励，其参考标准在训练期间单调收紧，以抑制多余的工具调用，同时不限制真正的多跳搜索。在微观层面，我们采用同策略蒸馏，从外部教师那里为失败的展开注入密集的 Token 级纠正信号，从而缓解稀疏结果奖励带来的信用分配缺陷。由于现有基准测试仅将准确率作为唯一指标而忽略了推理成本，我们引入了 IMEB，这是一个包含 300 个实例的人工策划基准，用于联合评估搜索能力和效率。在六个基准测试中，HyperEyes-30B 的准确率比最强的同类开源智能体高出 9.9%，且平均工具调用轮次减少了 5.3 倍。

## Abstract
Existing multimodal search agents process target entities sequentially, issuing one tool call per entity and accumulating redundant interaction rounds whenever a query decomposes into independent sub-retrievals. We argue that effective multimodal agents should search wider rather than longer: dispatching multiple grounded queries concurrently within a round. To this end, we present HyperEyes, a parallel multimodal search agent that fuses visual grounding and retrieval into a single atomic action, enabling concurrent search across multiple entities while treating inference efficiency as a first-class training objective. HyperEyes is trained in two stages. For cold-start supervision, we develop a Parallel-Amenable Data Synthesis Pipeline covering visual multi-entity and textual multi-constraint queries, curating efficiency-oriented trajectories via Progressive Rejection Sampling. Building on this, our central contribution, a Dual-Grained Efficiency-Aware Reinforcement Learning framework, operates at two levels. At the macro level, we propose TRACE (Tool-use Reference-Adaptive Cost Efficiency), a trajectory-level reward whose reference is monotonically tightened during training to suppress superfluous tool calls without restricting genuine multi-hop search. At the micro level, we adapt On-Policy Distillation to inject dense token-level corrective signals from an external teacher on failed rollouts, mitigating the credit-assignment deficiency of sparse outcome rewards. Since existing benchmarks evaluate accuracy as the sole metric, omitting inference cost, we introduce IMEB, a human-curated benchmark of 300 instances that jointly evaluates search capability and efficiency. Across six benchmarks, HyperEyes-30B surpasses the strongest comparable open-source agent by 9.9% in accuracy with 5.3x fewer tool-call rounds on average.

*   **核心问题**：现有的多模态搜索智能体（Multimodal Search Agents）在处理复杂查询时，通常采用**串行（Sequential）**的工具调用方式。例如，若一张图片中有多个实体需要识别，智能体往往每轮只处理一个实体，导致交互轮次多、延迟高、上下文冗余且易产生错误累积。
*   **研究动机**：作者认为高效的智能体应该“搜得更广，而非更长”（Search wider, not longer）。即在单轮交互中并发调度多个检索请求，将视觉定位（Grounding）与检索（Retrieval）融合，从而提升推理效率。

### 2. 方法论
HyperEyes 提出了一个并行多模态搜索框架，核心技术包括：
*   **统一基准搜索（Unified Grounded Search, UGS）**：将视觉定位从预处理步骤变为检索动作的一个参数。智能体可以在单轮内预测多个实体的边界框并同时发起并发检索，避免了“先裁剪再搜索”的串行瓶颈。
*   **双粒度效率感知强化学习（Dual-Grained Efficiency-Aware RL）**：
    *   **宏观层面（TRACE 奖励）**：提出“工具使用参考自适应成本效率”（TRACE）奖励。它设定一个动态的效率参考值（如工具调用轮次），该参考值在训练过程中随模型表现单调收紧，惩罚冗余调用，奖励在更少轮次内完成任务的行为。
    *   **微观层面（同策略蒸馏, OPD）**：针对强化学习中稀疏奖励导致的信用分配问题，在失败的尝试（Rollouts）中引入外部教师模型（如 235B 大模型）的 Token 级纠正信号，帮助模型学习正确的中间推理步骤。
*   **数据流水线**：
    *   **并行友好数据合成**：合成包含多实体视觉查询和多约束文本查询的数据集。
    *   **渐进式拒绝采样（PRS）**：在不同轮次预算下采样，仅保留成功且路径最短（最有效率）的轨迹作为冷启动监督信号。

### 3. 实验设计
*   **数据集与基准**：
    *   **IMEB（新提出）**：人工策划的“图像多实体基准”，包含 300 个实例，专门评估多实体定位与并发检索的准确率和效率。
    *   **通用基准**：MMSearch, FVQA, LiveVQA, BCVL, MMSearch+。
*   **对比方法**：
    *   **开源智能体**：DeepEyes-V2, MMSearch-R1, WebWatcher, VDR, REDSearch。
    *   **闭源模型**：Kimi-K2.5, Claude-Opus-4.6, Gemini-3.1-Pro。
*   **评估指标**：除了准确率（Acc），还引入了**成本感知得分（CAS）**，综合衡量准确率、Token 消耗和工具调用轮次。

*   **硬件环境**：使用了 8 个节点，共 **64 张 NVIDIA H20 (141GB) GPU**。
*   **训练时长**：
    *   **SFT 阶段**：30B 模型约 10 小时，235B 模型约 20 小时。
    *   **RL 阶段**：30B 模型约 48 小时，235B 模型约 72 小时。
*   **模型规模**：基于 Qwen3-VL 架构，训练了 30B 和 235B 两个版本。

### 5. 实验数量与充分性
*   **实验规模**：在 6 个主流基准上进行了全面测试，涵盖了浅层搜索到复杂多跳推理。
*   **消融实验**：非常充分。分别验证了数据过滤、TRACE 奖励机制、OPD 蒸馏、以及不同视觉定位范式（如代码裁剪 vs. 统一搜索）对结果的影响。
*   **客观性**：通过 3 个独立随机种子进行重复实验并报告标准差，验证了 RL 训练的稳定性；同时进行了抗干扰实验（注入噪声证据），证明了模型的鲁棒性。

### 6. 主要结论与发现
*   **性能领先**：HyperEyes-30B 在准确率上比最强的同类开源智能体高出 **9.9%**，同时工具调用轮次减少了 **5.3 倍**。
*   **效率与准确率互补**：实验发现，盲目增加工具调用次数并不一定提高准确率，反而可能引入噪声。HyperEyes 证明了通过强化学习约束效率，可以同时提升准确率。
*   **逼近闭源水平**：HyperEyes-235B 的表现已非常接近 Gemini-3.1-Pro，缩小了开源与顶级商业模型在多模态搜索领域的差距。

### 7. 优点
*   **效率优先**：首次将推理效率（交互轮次）作为强化学习的一等公民目标，解决了 Agent 领域普遍存在的“过度搜索”问题。
*   **架构创新**：UGS 动作空间的设计优雅地解决了多实体并发处理的难题。
*   **评估全面**：提出的 IMEB 基准和 CAS 指标填补了多模态 Agent 效率评估的空白。

### 8. 不足与局限
*   **教师模型依赖**：OPD 蒸馏需要一个同系列且更强大的教师模型，这限制了该方法在最顶尖规模模型上的直接应用。
*   **模态限制**：目前仅针对静态图像和文本，尚未扩展到视频或音频等动态多模态环境。
*   **闭源差距**：尽管表现优异，但在参数知识储备上与 Gemini 等顶级模型仍有微小差距。
