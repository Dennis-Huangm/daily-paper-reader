## 摘要
强化学习系统依赖于指定观测和奖励函数的环境接口，然而为新任务构建这些接口通常需要大量的人工努力。虽然最近的工作已经利用大语言模型（LLMs）实现了奖励设计的自动化，但这些方法假设观测是固定的，并没有解决合成完整任务接口这一更广泛的挑战。我们研究了从原始模拟器状态中发现强化学习任务接口的问题，其中必须同时生成观测映射和奖励函数。我们提出了 LIMEN（代码可在 https://github.com/Lossfunk/LIMEN 获取），这是一个由 LLM 引导的进化框架，它将候选接口生成为可执行程序，并利用策略训练反馈对其进行迭代优化。在涵盖运动和操作的新型离散网格世界任务和连续控制领域中，仅给定轨迹级的成功指标，观测和奖励的联合进化就能发现有效的接口，而单独优化其中任何一个组件在至少一个领域中都会失败。这些结果表明，从原始状态自动构建强化学习接口可以显著减少人工工程，并且观测和奖励组件通常受益于协同设计，因为在我们的评估套件中，单组件优化在至少一个领域中会出现灾难性的失败。

## Abstract
Reinforcement learning systems rely on environment interfaces that specify observations and reward functions, yet constructing these interfaces for new tasks often requires substantial manual effort. While recent work has automated reward design using large language models (LLMs), these approaches assume fixed observations and do not address the broader challenge of synthesizing complete task interfaces. We study RL task interface discovery from raw simulator state, where both observation mappings and reward functions must be generated. We propose LIMEN (Code available at https://github.com/Lossfunk/LIMEN), a LLM guided evolutionary framework that produces candidate interfaces as executable programs and iteratively refines them using policy training feedback. Across novel discrete gridworld tasks and continuous control domains spanning locomotion and manipulation, joint evolution of observations and rewards discovers effective interfaces given only a trajectory-level success metric, while optimizing either component alone fails on at least one domain. These results demonstrate that automatic construction of RL interfaces from raw state can substantially reduce manual engineering and that observation and reward components often benefit from co-design, as single-component optimization fails catastrophically on at least one domain in our evaluation suite.

### 1. 核心问题与整体含义
*   **研究动机**：在强化学习（RL）中，设计合适的**观测映射（Observation Mapping）**和**奖励函数（Reward Function）**是决定智能体性能的关键，但这一过程通常依赖专家手工工程，是RL应用的主要瓶颈。
*   **核心问题**：现有的自动化方法（如 Eureka）大多只关注奖励函数的生成，而假设观测空间是固定且调优过的。本文研究如何从原始模拟器状态（Raw State）中，利用大语言模型（LLM）同时自动合成完整的任务接口（观测+奖励）。

### 2. 方法论（LIMEN 框架）
*   **核心思想**：提出 **LIMEN**（Learning Interfaces via MDP-guided EvolutioN），将接口发现建模为一个双层优化问题。外层通过 LLM 引导的进化算法搜索接口程序，内层通过实际训练 RL 智能体来评估接口质量。
*   **关键技术细节**：
    *   **程序化表示**：将观测映射 $\phi$ 和奖励函数 $R$ 表示为可执行的 Python 代码（基于 JAX），直接操作原始模拟器变量。
    *   **进化搜索（MAP-Elites）**：使用质量-多样性（Quality-Diversity）算法维护一个存档，根据观测维度和奖励代码复杂度（AST 节点数）对接口进行分类，确保搜索的多样性。
    *   **LLM 作为变异算子**：利用 Claude Sonnet 4.6 根据任务描述、父代代码、训练反馈（如错误追踪、性能停滞）生成新的候选接口。
    *   **评估级联**：为了节省算力，采用“短预算”过滤机制，只有在简短训练中表现达标的接口才会进入完整的多种子训练评估。

### 3. 实验设计
*   **实验场景**：
    *   **XLand-MiniGrid**：离散网格世界任务，包括简单（拾取）、中等（关系放置）、困难（多步规则链）。
    *   **MuJoCo (MJX)**：连续控制任务，包括 Go1 四足机器人推力恢复和 Panda 机械臂轨迹跟踪。
*   **Benchmark 与对比方法**：
    *   **Sparse**：原始观测 + 二进制成功奖励。
    *   **Obs-Only**：仅进化观测映射，奖励固定。
    *   **Reward-Only**：仅进化奖励函数（类似于 Eureka/Text2Reward），观测固定。
    *   **Independent LLM Sampling**：不使用进化算法，直接从 LLM 采样 30 个接口。

### 4. 资源与算力
*   **硬件**：所有实验均在单张 **NVIDIA L4 GPU** 上运行。
*   **时长**：XLand 任务约需 1-3 小时，MuJoCo 任务约需 6-7 小时。总计运行时间约 36.1 小时。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 5 个不同性质的任务（从离散推理到连续控制）。
*   **充分性**：
    *   每个任务进行了 30 轮进化迭代。
    *   最终评估使用了 10 个独立随机种子以消除选择偏差。
    *   进行了消融实验（Obs-only vs Reward-only）和鲁棒性测试（分布偏移）。
*   **客观性**：实验对比了单一组件优化的局限性，并展示了进化算法相对于直接采样的显著优势，实验设计较为客观公平。

### 6. 主要结论与发现
*   **联合优化的必要性**：联合进化观测和奖励是唯一能在所有任务中避免灾难性失败的方法。
*   **瓶颈差异化**：网格世界任务主要是“观测受限型”（默认观测缺乏结构），而机器人任务主要是“奖励受限型”（默认奖励太稀疏）。
*   **模式发现**：LIMEN 自动发现了类似于人类专家的设计模式，如相对几何特征、多尺度编码、势能奖励（Potential-based shaping）和阶段性奖励。
*   **鲁棒性**：进化出的接口在动力学参数发生偏移时（如推力加倍）仍能保持一定的学习能力。

### 7. 优点与亮点
*   **端到端自动化**：首次实现了从原始模拟器状态到完整 MDP 接口的自动化合成。
*   **可解释性**：生成的接口是 Python 代码，人类可读、可调试且易于迁移。
*   **协同效应**：证明了观测和奖励的协同设计能显著降低 RL 算法的探索难度。

### 8. 不足与局限
*   **计算开销**：内层循环需要完整的 RL 训练，虽然使用了 JAX 加速，但对于大规模环境或视觉输入任务，计算成本依然高昂。
*   **特权信息依赖**：目前依赖于模拟器提供的结构化状态变量（如坐标、速度），在无法获取这些变量的真实世界场景中应用受限。
*   **搜索策略简单**：目前的进化策略（单候选迭代）相对基础，未来仍有优化空间。
*   **适应性风险**：在缺乏明确成功指标（Fitness Metric）的领域，该框架难以引导进化方向。
