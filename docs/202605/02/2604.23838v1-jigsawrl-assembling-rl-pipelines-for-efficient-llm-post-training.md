## 摘要
我们提出了 JigsawRL，这是一个高性价比的框架，它探索了流水线复用（Pipeline Multiplexing）作为强化学习并行性的一个新维度。JigsawRL 将每个流水线分解为子阶段图（Sub-Stage Graph），揭示了被阶段级系统所掩盖的阶段内和工作节点间的不平衡。在此抽象基础上，JigsawRL 通过动态资源分配解决复用干扰，通过在工作节点间迁移长尾 rollout 来消除碎片化利用，并将它们的协调建模为一个通过前瞻启发式算法解决的图调度问题。在 4-64 块 H100/A100 GPU 上，针对不同的智能体强化学习流水线和模型，JigsawRL 在同步强化学习上比 Verl 实现了高达 1.85 倍的吞吐量，在异步强化学习上比 StreamRL 和 AReaL 实现了 1.54 倍的吞吐量，并支持具有适度延迟权衡的异构流水线。

## Abstract
We present JigsawRL, a cost-efficient framework that explores Pipeline Multiplexing as a new dimension of RL parallelism. JigsawRL decomposes each pipeline into a Sub-Stage Graph that exposes the intra-stage and inter-worker imbalance hidden by stage-level systems. On this abstraction, JigsawRL resolves multiplexing interference through dynamic resource allocation, eliminates fragmented utilization by migrating long-tail rollouts across workers, and formulates their coordination as a graph scheduling problem solved with a look-ahead heuristic. On 4-64 H100/A100 GPUs across different agentic RL pipelines and models, JigsawRL achieves up to 1.85x throughput over Verl on synchronous RL, 1.54x over StreamRL and AReaL on asynchronous RL, and supports heterogeneous pipelines with moderate latency trade-off.

### JigsawRL：用于高效大语言模型后训练的强化学习流水线组装框架

#### 1. 核心问题与整体含义
随着大语言模型（LLM）后训练（如对齐、推理增强、智能体能力提升）的需求激增，强化学习（RL）流水线的**成本效率（Cost Efficiency）**成为了核心瓶颈。
*   **研究动机**：现有的 RL 框架（如 Verl）虽然优化了时间效率，但资源利用率极低（MFU 通常低于 10%）。
*   **核心痛点**：RL 过程中存在严重的**工作负载不平衡**。在 Rollout（采样）阶段，长尾序列（部分样本生成极长）导致大部分 GPU 核心在等待少数样本完成；在智能体任务中，多轮对话和外部工具调用进一步加剧了这种空闲和不平衡。
*   **整体含义**：本文提出了 **JigsawRL**，通过引入“流水线复用（Pipeline Multiplexing）”这一新的并行维度，让多个 RL 任务共享 GPU 资源，从而填补利用率低谷，大幅提升性价比。

#### 2. 方法论
JigsawRL 的核心思想是将粗粒度的 RL 阶段拆解并重新组合，其关键技术包括：
*   **子阶段图抽象（Sub-Stage Graph Abstraction）**：将传统的 Rollout、Training 等阶段细化为具有不同计算/内存特征的“子阶段”（如 Prefill 爆发期、低批次解码期、工具调用等待期）。利用步骤间的时序一致性，通过历史剖析（Profiling）构建该图。
*   **子阶段复用（Sub-Stage Multiplexing）**：在同一 GPU 上并发执行不同流水线的互补子阶段（例如：将内存受限的解码阶段与计算密集型的训练阶段配对）。
    *   **动态资源分配**：利用 NVIDIA MPS 或 Green Context 动态划分 SM（流处理器）比例，并根据内存压力调整微批次大小（Micro-batch size）。
*   **子阶段合并与迁移（Sub-Stage Merging & Migration）**：针对数据并行（DP）工作节点间的不平衡，将分散在多个节点上的长尾 Rollout 样本迁移到单个节点集中处理，释放其他节点的资源用于执行其他任务。
*   **前瞻性调度（Look-ahead Scheduling）**：采用启发式算法预测未来几步的执行路径，解决复用时的资源竞争和内存溢出（OOM）风险，寻找全局最优的调度方案。

#### 6. 主要结论与发现
*   **吞吐量提升**：在同步 RL 设置下，JigsawRL 比 Verl 提升了高达 **1.85 倍**的吞吐量；在异步设置下，比 StreamRL 和 AReaL 提升了 **1.54 倍**。
*   **成本效率**：通过空间复用，JigsawRL 显著降低了单位 Token 的货币成本，且随着 GPU 数量增加，其效率优势比传统方法更明显。
*   **延迟权衡**：虽然单流水线的步延迟平均增加了约 1.48 倍，但这远优于串行执行两个流水线（2 倍延迟），且换取了总吞吐量的巨大增益。
*   **异构支持**：能够高效处理不同大小模型（如 0.6B 与 8B 混合）的共存，小模型可以灵活填补大模型的利用率空隙。

#### 7. 优点
*   **维度创新**：开辟了“流水线复用”这一新并行维度，打破了单流水线优化的瓶颈。
*   **精细化编排**：子阶段图的抽象非常精准，捕捉到了智能体任务中特有的空闲模式。
*   **实用性强**：兼容现有的同步和异步 RL 算法，且支持异构模型混合部署，非常适合共享集群或 Serverless 环境。
*   **系统级优化**：结合了 SM 划分、KV 缓存重构和样本迁移，技术栈完整。

#### 8. 不足与局限
*   **延迟敏感性**：对于极度追求单次训练步延迟（而非总吞吐量）的任务，复用带来的延迟增加可能不被接受。
*   **模型架构限制**：目前主要针对稠密（Dense）模型进行了优化，尚未深入探讨混合专家模型（MoE）在专家级不平衡下的复用表现。
*   **内存开销**：虽然有调度优化，但同时加载多个模型权重和 KV 缓存对显存容量提出了更高要求，在显存受限的旧型号 GPU 上可能受限。
