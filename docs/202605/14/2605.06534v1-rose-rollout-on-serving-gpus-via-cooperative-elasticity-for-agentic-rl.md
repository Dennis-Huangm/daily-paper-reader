## 摘要
智能体强化学习（Agentic RL）已成为提升大语言模型（LLM）多步推理和工具使用能力的关键驱动力。然而，其效率受限于具有多轮环境交互的长尾 Rollout，使得静态 GPU 配置难以适配：过度配置会在落后者（stragglers）上浪费 GPU 资源，而配置不足则会增加竞争并减慢训练速度。我们观察到，生产环境中的推理服务集群通常会留有大量的 GPU 计算和显存余量。基于这一观察，我们提出了协作弹性（cooperative elasticity）：机会性地重新利用未充分利用的推理服务 GPU 来执行 Rollout。实现协作弹性并非易事，因为它必须在突发流量下保证推理服务的服务水平目标（SLO），并最小化通信开销。为了应对这些挑战，我们提出了 ROSE，这是一个协作式资源弹性后训练系统，它能安全地利用推理服务 GPU 上的空闲计算和显存资源，以加速智能体强化学习的 Rollout。ROSE 由三个组件组成：（1）一个 SLO 安全的共存执行器，通过高效的 GPU 显存和计算共享，在保证推理服务 SLO 的同时提高 Rollout 吞吐量；（2）一个跨集群权重传输引擎，利用权重分片和稀疏性实现跨集群的快速权重同步；（3）一个弹性 Rollout 调度器，动态配置协作容量，并在专用 Rollout GPU 和机会性推理服务 GPU 之间路由轨迹 Rollout。在多种模型规模和集群尺度上的实验表明，与最先进的资源固定型和弹性基准相比，ROSE 将平均端到端吞吐量提高了 1.20-3.31 倍。

## Abstract
Agentic reinforcement learning (RL) has emerged as a key driver for improving the multi-step reasoning and tool-use capabilities of LLMs. However, its efficiency is bottlenecked by long-tail rollouts with multi-turn environment interactions, making static GPU provisioning a poor fit: overprovisioning wastes GPUs on stragglers, while underprovisioning increases contention and slows training.   We observe that production serving clusters routinely leave substantial GPU compute and memory headroom. Based on this observation, we argue for cooperative elasticity: opportunistically repurposing underutilized serving GPUs to execute rollouts. Realizing cooperative elasticity is non-trivial because it must preserve serving Service Level Objectives (SLOs) under bursty traffic and minimize communication overhead. To address these challenges, we present ROSE, a cooperative, resource-elastic post-training system that safely harvests idle compute and memory on serving GPUs to accelerate agentic RL rollouts. ROSE consists of three components: (1) an SLO-safe co-serving executor that improves rollout throughput while preserving serving SLOs through efficient GPU memory and compute sharing; (2) a cross-cluster weight transfer engine that leverages weight shards and sparsity for fast weight synchronization across clusters; and (3) an elastic rollout scheduler that dynamically provisions cooperative capacity and routes trajectory rollouts across dedicated rollout GPUs and opportunistic serving GPUs. Experiments across multiple model sizes and cluster scales show that ROSE improves average end-to-end throughput by 1.20-3.31 x compared with state-of-the-art resource-fixed and elastic baselines.

### 论文总结：ROSE —— 通过协作弹性在推理服务 GPU 上实现智能体强化学习的 Rollout

#### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：智能体强化学习（Agentic RL）的训练效率受限于 **Rollout（采样）阶段**。该阶段涉及多轮环境交互，具有明显的“长尾效应”（部分采样任务极慢），导致静态分配 GPU 资源时，要么因等待长尾任务造成资源浪费，要么因资源不足导致训练停滞。
*   **研究背景**：工业界通常同时运行大规模的 **RL 训练集群** 和 **在线推理服务集群**。作者发现推理集群为了应对突发流量通常过度配置，导致日常 GPU 计算利用率（约 18.9%）和显存利用率（约 14.3%）极低。
*   **整体含义**：提出“协作弹性”（Cooperative Elasticity）概念，即在不影响在线服务质量（SLO）的前提下，动态“窃取”推理集群的空闲资源来加速 RL 的 Rollout 过程。

#### 2. 方法论
ROSE 系统由三个核心组件构成：
*   **SLO 安全的共存执行器（Co-serving Executor）**：
    *   **VMM 显存共享**：利用 CUDA 虚拟内存管理（VMM）实现异构模型（如推理用 7B，Rollout 用 32B）之间的物理页面动态重映射，无需重启进程即可调整显存分配。
    *   **抢占式显存策略**：保留 Rollout 的前缀缓存（Prefix Caching）以加速采样，但在推理流量激增时，立即强制回收显存页面。
    *   **双 SLO 准入控制**：基于预分析的算力开销，实时计算推理服务的首字延迟（TTFT）和单字延迟（TPOT）余量，仅在有余量时插入 Rollout 计算任务。
*   **跨集群权重传输引擎**：
    *   **稀疏性感知**：发现 RL 后训练中，相邻步骤的模型权重增量（Delta）具有极高的稀疏性（>95%），通过传输压缩后的稀疏增量大幅减少带宽压力。
    *   **分片感知与异步传输**：支持训练和推理集群使用不同的并行策略（TP/PP），自动映射权重分片，并与训练过程重叠执行。
*   **弹性 Rollout 调度器**：
    *   **轮次级路由**：在多轮交互的每一轮动态决定是在专用 GPU 还是借用的推理 GPU 上执行。
    *   **缓存亲和性放置**：优先将任务路由到持有该轨迹 KV Cache 的 GPU 上，减少重复计算。

#### 3. 实验设计
*   **数据集/场景**：
    *   **FrozenLake**：基础智能体任务，使用 Qwen3-8B 模型。
    *   **ALFWorld**：复杂的具身智能交互任务，使用 Qwen3-32B 模型。
*   **算法**：GRPO 和 DAPO（涉及冗余采样，对弹性需求更高）。
*   **对比基准（Benchmarks）**：
    *   **资源固定型**：ROLL（SOTA 框架）、AReaL（异步 RL 系统）。
    *   **资源弹性型**：RLBoost（利用竞价实例 Spot Instances）、$\lambda$RL（基于 Serverless GPU）。
    *   **推理共存型**：Prism（通用 GPU 多租户系统）、ServerlessLLM。

#### 4. 资源与算力
*   **GPU 型号**：NVIDIA **H800**。
*   **集群规模**：
    *   训练/专用采样集群：16 至 48 张 GPU。
    *   推理服务集群：16 至 64 张 GPU。
*   **网络**：集群内 400 Gbps InfiniBand，跨集群使用 200 Gbps 以太网（模拟跨数据中心场景）。
*   **训练时长**：实验涵盖了模型收敛的全过程（如 8B 模型 100 步，32B 模型 40 步）。

#### 5. 实验数量与充分性
*   **实验规模**：进行了端到端性能对比、不同算法下的吞吐量测试、扩展性分析（随借用 GPU 数量增加的收益）。
*   **消融实验**：详细测试了显存抢占策略、双 SLO 控制器、权重传输优化（异步/分片/稀疏）的各自贡献。
*   **充分性评价**：实验设计非常充分，不仅对比了吞吐量，还验证了模型收敛性（Critic Score）以及对在线服务 SLO 的影响（P99 延迟），确保了“协作”的安全性。

#### 6. 主要结论与发现
*   **吞吐量提升**：相比固定资源基准，ROSE 提升了 **1.20x 至 3.31x** 的端到端吞吐量。
*   **SLO 保障**：在借用资源的同时，推理服务的 P99 延迟保持在目标范围内，远优于传统的双向自动扩缩容方案。
*   **权重同步优化**：通过稀疏性优化，将 32B 模型的跨集群同步时间从数分钟降低至 **21 秒**。
*   **弹性价值**：在 DAPO 等需要动态调整采样量的算法中，ROSE 的优势尤为突出（最高 4.82x 提升）。

#### 7. 优点
*   **资源利用率极高**：开创性地将 RL 采样任务与在线推理服务深度融合，变废为宝。
*   **技术栈完整**：从底层的 CUDA 内存管理到上层的分布式调度，再到跨集群通信，提供了一套完整的系统解决方案。
*   **算法感知**：敏锐捕捉到 RL 权重更新的稀疏性特征，解决了跨数据中心传输的瓶颈。

#### 8. 不足与局限
*   **基础设施依赖**：要求组织内部同时拥有大规模训练和推理集群，且网络连接需达到一定带宽（虽然支持以太网，但极低带宽下收益会受限）。
*   **模型配对限制**：目前主要针对异构但架构相似（如 Qwen 系列不同尺寸）的模型共存进行了优化，对于架构差异极大的模型（如 Dense 模型与 MoE 模型共存）可能存在额外的显存碎片问题。
*   **极端流量风险**：如果推理服务遭遇持续性的全集群超高峰值流量，ROSE 能借用的资源将枯竭，此时系统退化为普通固定资源模式。
