## 摘要
基于可验证奖励的强化学习（RLVR）显著提升了大语言模型（LLM）的推理能力，特别是在涉及工具使用等环境交互的多轮智能体场景中。然而，由于极高的计算需求，微调此类模型仍然昂贵得令人望而却步，限制了其普及性。我们提出了 MARLaaS（多租户异步强化学习即服务），这是一个支持跨多个用户和任务进行并发强化学习微调的系统。我们的方法基于两个核心思想：（1）通过轻量级 LoRA 适配器在租户间共享基础模型；（2）采用解耦的异步架构，将 rollout 生成、环境交互和策略训练分解为独立调度的阶段。这种设计使任务能够以事件驱动的方式按照各自的节奏在强化学习流水线中推进，从而减少了跨任务干扰、空闲时间以及端到端延迟。在多任务设置下（我们报告了多达 32 个并发任务），MARLaaS 在达到单任务最先进性能的同时，将加速器利用率提高了多达 4.3 倍，并将端到端训练时间缩短了 85%。

## Abstract
Reinforcement Learning from Verifiable Rewards (RLVR) has significantly improved the reasoning capabilities of large language models (LLMs), particularly in multi-turn agentic settings involving environment interaction like tool use. However, fine-tuning such models remains prohibitively expensive due to high computational requirements, limiting accessibility. We propose MARLaaS (Multi-tenant Asynchronous RL as a Service), a system for concurrent RL fine-tuning across multiple users and tasks. Our approach is based on two key ideas: (1) sharing a base model across tenants using lightweight LoRA adapters, and (2) a disaggregated asynchronous architecture that decouples rollout generation, environment interaction, and policy training into independently scheduled stages. This design enables tasks to progress through the RL pipeline at their own pace in an event-driven manner, reducing cross-task interference, idle time, and end-to-end latency. In multi-task settings (we report up to 32 concurrent tasks), MARLaaS achieves single-task state-of-the-art performance while improving accelerator utilization by up to 4.3x and reducing end-to-end training time by 85%.

### 1. 核心问题与研究动机
*   **核心问题**：大语言模型（LLM）通过可验证奖励强化学习（RLVR）进行微调（如提升推理和智能体能力）时，计算成本极高且资源利用率低下。
*   **研究背景**：传统的 RLVR 训练包含生成（Rollout）、环境交互（如工具调用）和策略训练三个阶段。在现有系统中，这些阶段通常是同步且顺序执行的，导致“计算气泡”：生成时训练资源闲置，工具调用时加速器等待外部响应。此外，多用户（多租户）场景下，为每个任务独立分配资源会导致巨大的内存开销。

### 2. 方法论
MARLaaS 提出了一个多租户异步强化学习系统，核心思想包括：
*   **轻量级多租户共享**：使用 LoRA 适配器技术，让多个租户共享同一个冻结的基础模型，仅需为每个任务维护极小的适配器参数和优化器状态，从而支持跨任务的 Rollout 批处理。
*   **解耦的异步架构**：将系统拆分为三个独立组件：
    *   **多任务管理器 (M)**：维护各任务的 LoRA 参数、版本计数器和全局训练缓冲区。
    *   **Rollout 引擎**：基于 vLLM，利用多 LoRA 批处理并行生成轨迹。
    *   **训练引擎**：从缓冲区提取轨迹并执行策略更新。
*   **异步调度逻辑**：任务不再需要全局同步。Rollout 引擎在生成完一个版本后立即进入下一轮，训练引擎则在后台持续处理已完成的轨迹。系统通过版本控制确保每个任务仅在自身最新的策略版本上进行训练，避免了有害的策略陈旧性（Staleness）。
*   **非对称设计**：针对 RLVR 中 Rollout 耗时远大于训练（10-100倍）的特点，系统优先保证 Rollout 的并发吞吐量，而对训练更新进行顺序调度以降低延迟。

### 3. 实验设计
*   **数据集/场景**：
    *   **GSM8k**：小学数学推理。
    *   **AMC12**：竞赛级数学难题（长推理链）。
    *   **Agentic Search**：智能体搜索任务，涉及 Wikipedia API 调用（高环境延迟）。
*   **Benchmark 与对比方法**：
    *   **Single-Disaggregated**：单任务独占资源，顺序执行。
    *   **Single-Collocated**：单任务共享资源池，但仍为同步执行。
    *   **Multi-LoRA (Sync)**：多任务共享资源，但强制执行全局同步屏障。
*   **评估指标**：加速器利用率、训练吞吐量（steps/hr）、端到端作业完成时间、首步延迟（TTFS）和每步延迟（TPTS）。

### 4. 资源与算力
*   **硬件环境**：使用了两个节点的 **Ascend（昇腾）集群**，每个节点包含 16 个 NPU（共 **32 个 NPU**），每个 NPU 拥有 64GB 显存。
*   **模型规模**：评估了 **Qwen3-0.6B、14B 和 32B** 三种规模的模型。
*   **算力分配**：根据模型大小分配最少数量的 NPU 用于 FSDP 训练（如 0.6B 用 2 个，32B 用 16 个），其余 NPU 全部投入 Rollout 生成。

### 5. 实验数量与充分性
*   **实验规模**：报告了多达 **32 个并发任务** 的扩展性实验。
*   **消融实验**：分别验证了“异步执行”和“多 LoRA 共享”对性能的贡献。
*   **充分性评价**：实验覆盖了从轻量级到中大规模模型，且涵盖了纯推理和复杂智能体交互场景。对比了多种基准线，并分析了用户侧延迟指标，实验设计较为客观、全面，能够证明系统在多租户环境下的优越性。

### 6. 主要结论与发现
*   **性能提升**：在 32 个并发任务下，MARLaaS 将加速器利用率提升了 **4.3 倍**，总吞吐量提升了 **5.7 倍**。
*   **时间缩减**：在保持与单任务训练相当的奖励（Reward）水平前提下，端到端训练时间缩短了 **85%**。
*   **响应性**：相比顺序执行，MARLaaS 显著降低了任务的首步延迟（TTFS），使多用户请求能更快得到响应。
*   **瓶颈转移**：发现异步执行是效率提升的主要驱动力，而多 LoRA 批处理则进一步通过空间复用强化了增益。

### 7. 优点与亮点
*   **高效性**：成功解决了 RLVR 训练中严重的资源闲置问题，特别是在有外部工具调用的智能体场景中表现优异。
*   **无损性能**：与通过引入“策略陈旧性”来换取速度的方法不同，MARLaaS 通过跨任务重叠（而非任务内陈旧化）实现异步，保证了训练质量。
*   **高扩展性**：支持大量并发 LoRA 任务，为“强化学习即服务（RL-TaaS）”提供了可落地的架构参考。

### 8. 不足与局限
*   **训练引擎瓶颈**：目前训练更新是顺序执行的，当并发任务极多时，训练引擎可能成为新的串行瓶颈。
*   **内存限制**：尽管使用了 LoRA，但 KV 缓存（KV-Cache）容量仍限制了长文本或复杂智能体任务的并发上限。
*   **缺乏动态调度**：目前尚未实现针对任务优先级的动态资源调整或自适应并发控制。
*   **硬件依赖**：实验主要在昇腾架构上完成，虽然原理通用，但在其他硬件（如 NVIDIA GPU）上的跨平台表现未直接展示。
