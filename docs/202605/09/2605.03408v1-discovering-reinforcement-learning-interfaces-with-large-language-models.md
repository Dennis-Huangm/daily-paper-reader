## 摘要
强化学习系统依赖于指定观测和奖励函数的环境接口，但为新任务构建这些接口通常需要大量的人工工作。虽然近期研究已利用大语言模型（LLMs）实现了奖励设计的自动化，但这些方法假设观测是固定的，并未解决合成完整任务接口这一更广泛的挑战。我们研究了从原始模拟器状态中发现强化学习任务接口的问题，即必须同时生成观测映射和奖励函数。我们提出了 LIMEN（代码见 https://github.com/Lossfunk/LIMEN），这是一个由 LLM 引导的进化框架，它将候选接口生成为可执行程序，并利用策略训练反馈进行迭代优化。在涵盖运动和操纵的新型离散网格世界任务和连续控制领域中，仅给定轨迹级成功指标，观测与奖励的联合进化便能发现有效的接口，而单独优化其中任何一个组件在至少一个领域中都会失败。这些结果表明，从原始状态自动构建强化学习接口可以显著减少人工工程量，且观测和奖励组件通常受益于协同设计，因为在我们的评估套件中，单组件优化在至少一个领域中会出现灾难性的失败。

## Abstract
Reinforcement learning systems rely on environment interfaces that specify observations and reward functions, yet constructing these interfaces for new tasks often requires substantial manual effort. While recent work has automated reward design using large language models (LLMs), these approaches assume fixed observations and do not address the broader challenge of synthesizing complete task interfaces. We study RL task interface discovery from raw simulator state, where both observation mappings and reward functions must be generated. We propose LIMEN (Code available at https://github.com/Lossfunk/LIMEN), a LLM guided evolutionary framework that produces candidate interfaces as executable programs and iteratively refines them using policy training feedback. Across novel discrete gridworld tasks and continuous control domains spanning locomotion and manipulation, joint evolution of observations and rewards discovers effective interfaces given only a trajectory-level success metric, while optimizing either component alone fails on at least one domain. These results demonstrate that automatic construction of RL interfaces from raw state can substantially reduce manual engineering and that observation and reward components often benefit from co-design, as single-component optimization fails catastrophically on at least one domain in our evaluation suite.

*   **核心问题**：能否利用大语言模型（LLM）从原始模拟器状态中，同时自动合成可执行的观测映射程序和奖励函数程序？

### 2. 方法论：LIMEN 框架
论文提出了 **LIMEN**（Learning Interfaces via MDP-guided EvolutioN），其核心思想是将接口发现视为一个双层优化问题：
*   **核心思想**：将观测 $\phi$ 和奖励 $R$ 表示为 Python 程序。外层循环利用 LLM 作为变异算子进行进化搜索；内层循环通过训练实际的 RL 智能体来评估接口的“适应度”（Fitness）。
*   **关键技术细节**：
    *   **程序化表示**：接口由 JAX 兼容的 Python 代码组成，直接操作原始模拟器变量。
    *   **进化策略**：采用 **MAP-Elites** 算法维护一个“质量-多样性”存档。存档基于观测维度和奖励代码复杂度（AST 节点数）进行分箱，确保搜索不会陷入单一策略。
    *   **LLM 引导变异**：使用 LLM（如 Claude 3.5 Sonnet）根据任务描述、父代代码、训练反馈（如成功率、错误日志）生成新的候选接口。
    *   **评估级联**：为了节省算力，先进行短时间的“预算截断”训练筛选候选者，通过后再进行完整的多种子训练评估。

### 6. 主要结论与发现
*   **协同设计的必要性**：联合优化（Joint）在所有任务中均表现最优。
*   **互补的失败模式**：
    *   **观测受限**：在复杂的网格世界中，Reward-only 失败，因为原始观测缺乏空间关系。
    *   **奖励受限**：在机器人控制中，Obs-only 失败，因为稀疏奖励无法提供足够的学习信号。

*   **可解释性**：发现的接口展现了人类专家常用的模式，如相对几何特征、势能奖励函数（Potential-based rewards）和阶段性里程碑奖励。

### 7. 优点与亮点
*   **端到端自动化**：首次实现了从原始状态到完整 MDP 接口（观测+奖励）的自动程序化合成。
*   **可解释的代码产出**：生成的接口是 Python 代码，人类可读、可调试且易于迁移。
*   **质量-多样性搜索**：引入 MAP-Elites 避免了进化搜索过早收敛到局部最优。
*   **鲁棒性**：进化的接口在动力学参数发生偏移时（如推力加倍）仍能保持一定的学习能力。

### 8. 不足与局限
*   **计算成本**：虽然使用了 JAX 加速，但内层循环需要完整的 RL 训练，对于大规模环境或视觉输入任务，算力需求将呈指数级增长。
*   **依赖特权信息**：目前假设可以访问模拟器的结构化状态变量（如坐标、速度），在只有像素输入的真实场景中无法直接应用。
*   **进化策略简单**：目前每代仅生成一个候选者，进化算法（MAP-Elites）的配置较为基础，仍有优化空间。
*   **适应度指标依赖**：需要一个可靠的轨迹级成功指标（Success Metric）来引导进化，在某些定义模糊的任务中可能难以获取。
