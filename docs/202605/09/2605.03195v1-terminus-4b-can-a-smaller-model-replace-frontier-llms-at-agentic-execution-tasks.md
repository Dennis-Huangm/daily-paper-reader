## 摘要
现代编程智能体越来越多地将专门的子任务委托给子智能体，这些子智能体是更小、更专注的智能体循环，负责处理搜索、调试或终端执行等特定职责。这种架构模式通过将冗长的输出（如构建日志、测试结果等）隔离在子智能体上下文中，从而保持主智能体的上下文窗口整洁。通常，当智能体在这些任务中使用子智能体时，会采用前沿模型作为子智能体。在本文中，我们研究了经过微调的小语言模型（SLM）在智能体终端执行任务中是否能达到与前沿模型相当的性能。我们提出了 Terminus-4B，这是一个通过监督微调（SFT）和使用基于准则的 LLM-as-judge 奖励的强化学习（RL）进行后训练的 Qwen3-4B 模型，专门针对该任务。在涵盖各种前沿模型、训练消融实验和主智能体配置的广泛评估中，我们发现，与无子智能体基线相比，Terminus-4B 能够将主智能体的 token 使用量减少高达约 30%，且不会影响在 SWE-Bench Pro 和我们内部的 SWE-Bench C# 基准测试（该基准测试通常包含大量冗长的执行任务）上的性能。此外，Terminus-4B 改善了关键指标，表明主智能体更加依赖子智能体的输出，并减少了自身执行终端任务的次数。我们发现，该模型不仅缩小了原始 Qwen 模型与 Claude Sonnet / Opus / GPT-5.3-Codex 等前沿模型之间的差距，甚至往往在性能上有所超越。

## Abstract
Modern coding agents increasingly delegate specialized subtasks to subagents, which are smaller, focused agentic loops that handle narrow responsibilities like search, debugging or terminal execution. This architectural pattern keeps the main agent's context window clean by isolating verbose outputs (e.g. build logs, test results, etc.) within the subagent context. Typically when agents employ subagents for such tasks, they use frontier models as these subagents. In this paper, we investigate whether a finetuned small language model (SLM) can achieve comparable performance to frontier models in the task of agentic terminal execution. We present Terminus-4B, which is a post-trained Qwen3-4B model via Supervised Finetuning (SFT) and Reinforcement Learning (RL) using rubric-based LLM-as-judge reward, specifically for this task. In our extensive evaluation spanning various frontier models, training ablations and main agent configurations, we find that Terminus-4B is able to reduce the token usage of the main agent by up to ~30% compared to the No Subagent baseline with no impact to agent performance on benchmarks like SWE-Bench Pro and our internal SWE-Bench C# benchmark, which tends to be heavy in verbose execution tasks. Furthermore, Terminus-4B improves key metrics showing the main agent relying on the outputs of the subagent and doing fewer terminal execution tasks by itself. We see that our model not only closes the gap between the Vanilla Qwen model and frontier models like Claude Sonnet / Opus / GPT-5.3-Codex, but often even exceeds their performance.

*   **核心问题**：现代编程智能体在执行构建、测试和诊断任务时，终端输出（如编译日志、测试结果）会产生海量 Token，迅速填满主智能体的上下文窗口，导致推理成本激增且效率下降。
*   **研究动机**：目前业界倾向于使用子智能体（Subagent）模式来隔离这些冗长输出，但通常仍使用 GPT-4 或 Claude 等昂贵模型作为子智能体。作者希望验证：一个参数量仅为 4B 的专用小模型，是否能在保证任务成功率的前提下，显著降低成本并优化上下文管理。

### 2. 方法论
*   **核心思想**：将终端执行任务解耦，训练一个专用的“执行子智能体”（Execution Subagent），它负责运行命令并向主智能体返回结构化的精简摘要（`<final_answer>`）。
*   **关键技术细节**：
    *   **模型基础**：选用 Qwen3-4B 作为基座模型。
    *   **两阶段训练流程**：
        1.  **有监督微调 (SFT)**：利用内部遥测数据中的专家轨迹进行初步训练，让模型学会工具调用规范和摘要格式。
        2.  **强化学习 (RL)**：采用 **GRPO（群组相对策略优化）** 算法。为了解决终端任务难以自动评分的问题，引入了“基于准则的 LLM-as-judge”奖励机制。
    *   **奖励设计**：
        *   将原始轨迹转换为“执行计划”（Execution Plan）。
        *   使用前沿模型根据 14 个维度（执行质量、失败模式、最终答案质量）进行打分。
        *   **公式**：$r = (1 - \alpha)(\bar{s}_{pos} - \bar{s}_{pit}) + \alpha \cdot \bar{s}_{fa}$（结合了正面得分、负面惩罚和最终答案质量）。
    *   **解耦训练框架**：在 RL 阶段，将子智能体与主智能体解耦，使用轻量级模型模拟主智能体发出指令，从而实现低成本、高并发的 Rollout（环境采样）。

### 3. 实验设计
*   **数据集 / 场景**：
    *   **SWE-Bench Pro**：多语言基准测试（Python, JS, Java, Go 等）。
    *   **SWE-Bench C#**：内部构建的针对 C# 语言的基准测试，包含大量重型执行任务。
*   **对比方法**：
    *   **基线**：无子智能体模式（主智能体直接操作终端）。
    *   **前沿模型子智能体**：使用 Claude Opus / Sonnet 作为子智能体。
    *   **消融版本**：原始 Qwen3-4B (Vanilla)、仅经过 SFT 的版本 (SFT-4B)。
*   **主智能体配置**：分别测试了 GPT-5.3-Codex、Claude Sonnet 4.6 和 Claude Opus 4.6 作为“大脑”时的表现。

### 4. 资源与算力
*   **硬件**：使用了一个包含 **8 台 NVIDIA A100/H100 GPU** 的单节点进行训练。
*   **推理**：部署在 Fireworks AI 平台上。
*   **训练细节**：SFT 训练 2 个 Epoch；RL 阶段每组采样 8 个轨迹（G=8），全局 Batch Size 为 64。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了跨语言验证、跨主模型验证、工具配置消融（如禁用主智能体终端权限）以及 LLM-Judge 人工模拟评估。
*   **充分性**：实验设计非常详尽。作者不仅关注最终的解决率（Resolve Rate），还深入分析了行为指标，如“主智能体对子智能体的不信任率”（即子智能体运行后主智能体是否又亲自重跑命令），这证明了实验的客观性和深度。

### 6. 主要结论与发现
*   **Token 节省**：Terminus-4B 相比无子智能体基线，可减少主智能体约 **30% 的 Token 消耗**。
*   **性能对标**：在执行任务上，Terminus-4B 的表现达到甚至在某些维度超过了 Claude Sonnet 和 GPT-5.3-Codex。
*   **行为改变**：主智能体直接调用终端的次数减少了 62-79%，表明主智能体高度信任 Terminus-4B 返回的摘要。
*   **训练必要性**：实验证明 SFT 是 RL 成功的基石，单纯靠 RL 无法让 4B 模型从零学会复杂的终端交互逻辑。

### 7. 优点
*   **实用性极强**：直接针对当前 AI Agent 落地中的“上下文膨胀”和“高昂成本”痛点。
*   **奖励机制创新**：通过将复杂轨迹转化为结构化“执行计划”再评分，解决了长程任务奖励稀疏和难以量化的问题。
*   **架构优雅**：解耦了主从智能体的训练，使得 SLM 的强化学习变得高效且经济。

### 8. 不足与局限
*   **平台覆盖有限**：目前主要集中在 Unix/Bash 环境，未覆盖 Windows PowerShell 或 Mac Zsh 的特有指令。

*   **模型多样性不足**：仅在 Qwen 系列上进行了验证，尚未证明该方案在 Llama 或其他 SLM 家族上的迁移效果。
