## 摘要
大语言模型 (LLM) 编程智能体越来越多地在长周期的软件工程环节中处理代码库、终端、测试和执行轨迹。持久化记忆非常有用，但静态向量存储或通用的检索增强生成 (RAG) 对于强化学习 (RL) 代码开发来说是不够的，因为微小的细节可能会改变 Bellman 目标、终止掩码 (terminal masks)、梯度流或验证声明。本文提出了 RL Developer Memory，这是一种面向 RL 编程智能体的本地优先、原生支持模型上下文协议 (MCP) 的开发者记忆架构。它将记忆选择视为一个记录在案的上下文决策过程：issue_match 对候选项进行排序并记录遥测数据，issue_feedback 将原始标签映射到有界奖励，而 issue_record_resolution 将经过验证的解决方案与早期的检索事件联系起来。系统部署了一个确定性排序器，同时一个上下文老虎机 (contextual-bandit) 残差策略以影子模式运行，且仅能通过保守的离线策略评估 (OPE) 门控影响金丝雀行为。RL/控制记忆需要“理论到代码”的元数据以及经过评审门控的治理。该系统在一个包含 200 个案例的确定性基准测试上进行了评估，涵盖了 RL 算法漏洞、硬负样本、评审门控的 RL/控制案例以及低风险失败。在同提交对比中，确定性控制和完整的影子/OPE 配置均实现了 80.0% 的预期决策准确率和 100.0% 的硬负样本抑制；完整配置增加了学习遥测数据，而非准确率提升。静态验证通过了 11/11 项检查；动态集成通过了 10/10 个案例。证据报告了局限性：不支持主动学习策略部署和官方客户端 MCP 互操作性，实时完整配置的延迟有所增加，且仍存在 40 个残余的非 RL 故障。本文的贡献在于提出了一种具有明确声明边界的可审计记忆控制架构，而非通用的编程智能体改进声明。

## Abstract
Large language model (LLM) coding agents increasingly operate over repositories, terminals, tests, and execution traces across long software-engineering episodes. Persistent memory is useful, but static vector stores or generic retrieval-augmented generation (RAG) are insufficient for reinforcement-learning (RL) code development, where small details can alter Bellman targets, terminal masks, gradient flow, or validation claims. This paper presents RL Developer Memory, a local-first, Model Context Protocol (MCP)-native developer-memory architecture for RL coding agents. It treats memory selection as a logged contextual decision process: issue_match ranks candidates and records telemetry, issue_feedback maps raw labels to bounded rewards, and issue_record_resolution links verified resolutions to earlier retrieval events. A deterministic ranker remains deployed, while a contextual-bandit residual policy runs in shadow mode and can affect canary behavior only through conservative off-policy-evaluation (OPE) gates. RL/control memories require theory-to-code metadata and review-gated governance. The system is evaluated on a deterministic 200-case benchmark with RL algorithm bugs, hard negatives, review-gated RL/control cases, and low-risk failures. In the same-commit comparison, deterministic control and full shadow/OPE both achieve 80.0% expected-decision accuracy and 100.0% hard-negative suppression; the full configuration adds learning telemetry rather than accuracy gain. Static validation passed 11/11 checks; dynamic integration passed 10/10 cases. The evidence reports limits: active learned-policy deployment and official-client MCP interoperability are unsupported, live full-configuration latency regresses, and 40 residual non-RL failures remain. The contribution is an auditable memory-control architecture with explicit claim boundaries, not a universal coding-agent improvement claim.

### 1. 核心问题与整体含义
*   **研究动机**：现有的 LLM 编程智能体在处理复杂软件工程任务时，通常依赖简单的 RAG（检索增强生成）或静态向量数据库。然而，在 **强化学习（RL）** 领域，代码的微小差异（如 Bellman 目标的实现、梯度截断位置、终止掩码处理等）会对算法收敛产生决定性影响。
*   **核心矛盾**：通用的记忆检索往往过于“模糊”，无法区分语义相似但逻辑迥异的 RL 实现细节。此外，在线强化学习在开发环境中的直接应用存在安全风险（可能引入错误补丁）。
*   **整体含义**：本文旨在构建一个**可审计、安全门控且原生支持 MCP 协议**的开发者记忆系统，将记忆检索从简单的“搜索”提升为受控的“决策过程”。

### 2. 方法论
*   **核心思想**：将记忆检索建模为一个**带日志的上下文决策过程**，引入影子策略（Shadow Policy）和离线策略评估（OPE）来确保记忆更新的安全性。
*   **关键技术细节**：
    *   **MCP 原生架构**：利用模型上下文协议（Model Context Protocol）标准化工具接口，包括 `issue_match`（匹配）、`issue_feedback`（反馈）和 `issue_record_resolution`（记录解决）。
    *   **反馈归一化**：将开发者零散的反馈（如“有用”、“错误”）映射到有界的规范奖励值（Reward），例如 `fix_verified` 对应 +1.0，`false_positive` 对应 -1.0。
    *   **延迟奖励关联**：通过会话 ID 和项目范围，将后期验证的修复结果（Delayed Reward）回溯关联到早期的检索事件，解决信用分配问题。
    *   **影子上下文老虎机（Shadow Contextual Bandit）**：系统部署确定性排序器作为基准，同时运行一个线性残差策略进行学习。只有通过 OPE 门控验证后，学习到的策略才能进入“金丝雀”发布阶段。
    *   **理论到代码（Theory-to-Code）追踪**：RL 记忆条目包含元数据，将数学公式（如 TD 误差）与代码锚点（文件、行号）绑定，并设有验证层级（Validation Tiers）。

### 3. 实验设计
*   **数据集/场景**：使用了一个包含 **200 个确定性案例** 的 RL 开发者记忆基准测试。
*   **Benchmark 组成**：
    *   160 个 RL 相关案例（涵盖 DQN, PPO, SAC, TD3, GAE 等算法漏洞）。
    *   40 个非 RL 的通用开发者记忆案例（路径处理、别名冲突等）。
    *   包含 80 个“硬负样本”（Hard Negatives），即语义极度相似但解决方案不同的干扰项。

### 5. 实验数量与充分性
*   **实验规模**：完成了 200 个案例的五种模式运行（离线控制、离线完整、在线影子、实时控制、实时完整），以及 11 项静态验证和 10 项动态集成测试。
*   **充分性评价**：

    *   **公平性**：采用了“同提交对比”（Same-commit comparison），确保了基准测试的严谨。
    *   **不足**：缺乏在 SWE-bench 等通用大规模基准上的端到端评估；消融实验（V0-V4）缺失，导致无法量化单个组件（如理论元数据）的具体贡献。

### 6. 主要结论与发现
*   **准确性**：确定性基准和完整配置均达到了 **80.0% 的决策准确率** 和 **100.0% 的硬负样本抑制**。
*   **功能验证**：完整配置成功实现了学习遥测数据的记录（60.5% 的统计更新率），证明了架构的可训练性。
*   **性能代价**：实时运行下，p95 延迟显著增加（从约 447ms 增加到 852ms），主要源于指标统计和 OPE 报告的开销。
*   **失败分析**：残余的 40 个失败案例全部集中在非 RL 领域（如 Windows 挂载路径处理），说明系统在通用路径兼容性上仍有欠缺。

### 7. 优点
*   **高安全性**：通过影子模式和 OPE 门控，防止了未经证实的学习策略干扰开发环境。
*   **可审计性**：为编程智能体的记忆检索提供了详尽的决策日志和理论依据。
*   **领域针对性强**：深刻理解 RL 开发的痛点，引入了“理论到代码”的映射机制。
*   **标准化**：采用 MCP 协议，具有良好的工具集成潜力。

### 8. 不足与局限
*   **延迟回归**：系统开销较大，尤其是在实时遥测和报告生成方面。
*   **覆盖范围有限**：目前仅在 200 个特定案例上验证，缺乏真实世界大规模代码库的端到端成功率数据。
*   **互操作性**：由于环境限制，未能在官方 MCP 客户端上完成互操作性测试。
*   **通用性不足**：在处理非 RL 的基础软件工程任务（如路径、作用域）时表现较弱。
