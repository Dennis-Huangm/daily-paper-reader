## 摘要
现代编程智能体（coding agents）越来越多地将专门的子任务委托给子智能体（subagents），这些子智能体是更小、更专注的智能体循环，负责处理搜索、调试或终端执行等狭窄职责。这种架构模式通过将冗长的输出（如构建日志、测试结果等）隔离在子智能体上下文中，从而保持主智能体的上下文窗口整洁。通常，当智能体在这些任务中使用子智能体时，它们会使用前沿模型作为子智能体。在本文中，我们研究了经过微调的小语言模型（SLM）在智能体终端执行任务中是否能达到与前沿模型相当的性能。我们提出了 Terminus-4B，这是一个通过监督微调（SFT）和使用基于评分标准的 LLM-as-judge 奖励的强化学习（RL）进行后训练的 Qwen3-4B 模型，专门针对该任务。在涵盖各种前沿模型、训练消融实验和主智能体配置的广泛评估中，我们发现，与“无子智能体”基准相比，Terminus-4B 能够将主智能体的 token 使用量减少高达约 30%，且不会影响在 SWE-Bench Pro 和我们内部的 SWE-Bench C# 基准测试（该基准测试通常包含大量冗长的执行任务）上的智能体性能。此外，Terminus-4B 改进了关键指标，表明主智能体依赖子智能体的输出，并减少了自身执行终端任务的次数。我们观察到，我们的模型不仅缩小了原始 Qwen 模型与 Claude Sonnet / Opus / GPT-5.3-Codex 等前沿模型之间的差距，而且往往甚至超过了它们的性能。

## Abstract
Modern coding agents increasingly delegate specialized subtasks to subagents, which are smaller, focused agentic loops that handle narrow responsibilities like search, debugging or terminal execution. This architectural pattern keeps the main agent's context window clean by isolating verbose outputs (e.g. build logs, test results, etc.) within the subagent context. Typically when agents employ subagents for such tasks, they use frontier models as these subagents. In this paper, we investigate whether a finetuned small language model (SLM) can achieve comparable performance to frontier models in the task of agentic terminal execution. We present Terminus-4B, which is a post-trained Qwen3-4B model via Supervised Finetuning (SFT) and Reinforcement Learning (RL) using rubric-based LLM-as-judge reward, specifically for this task. In our extensive evaluation spanning various frontier models, training ablations and main agent configurations, we find that Terminus-4B is able to reduce the token usage of the main agent by up to ~30% compared to the No Subagent baseline with no impact to agent performance on benchmarks like SWE-Bench Pro and our internal SWE-Bench C# benchmark, which tends to be heavy in verbose execution tasks. Furthermore, Terminus-4B improves key metrics showing the main agent relying on the outputs of the subagent and doing fewer terminal execution tasks by itself. We see that our model not only closes the gap between the Vanilla Qwen model and frontier models like Claude Sonnet / Opus / GPT-5.3-Codex, but often even exceeds their performance.

### 1. 核心问题与研究动机
*   **研究动机**：现代编码智能体（如解决 GitHub Issue 的智能体）在执行任务时，需要频繁运行构建、安装依赖和测试命令。这些操作会产生海量的终端输出（如数万 token 的构建日志），迅速填满主智能体的上下文窗口，导致推理成本激增并干扰其核心逻辑判断。
*   **核心问题**：能否设计一个专门负责“终端执行”的子智能体（Subagent），使用参数量较小的模型（如 4B），在不降低任务成功率的前提下，通过生成简洁的执行摘要来减少主智能体的上下文负担和成本？

### 2. 方法论
*   **核心思想**：采用“编排者-执行者”架构。主智能体将执行任务委托给 **Execution Subagent**，后者在独立上下文中运行命令，仅向主智能体返回结构化的 XML 摘要（`<final_answer>`）。
*   **关键技术细节**：
    *   **模型基础**：选用 Qwen3-4B 作为基础模型。
    *   **两阶段训练**：
        1.  **有监督微调 (SFT)**：利用内部遥测数据中的专家轨迹进行微调，让模型学会使用终端工具和输出格式。
        2.  **强化学习 (RL)**：使用 **GRPO (Group Relative Policy Optimization)** 算法。为了解决执行任务难以用简单成功/失败定义的难题，研究者设计了**基于评分标准（Rubric）的 LLM-as-judge 奖励机制**。
    *   **执行计划（Execution Plan）**：在 RL 阶段，不直接对比冗长的原始轨迹，而是将轨迹压缩为“执行计划”，由前沿模型根据 14 个维度（如执行质量、失败模式、摘要准确性等）对候选轨迹与参考轨迹进行评分。
*   **公式/流程**：奖励函数 $r = (1 - \alpha)(\bar{s}_{pos} - \bar{s}_{pit}) + \alpha \cdot \bar{s}_{fa}$，综合了正面得分、负面惩罚和最终答案质量。

### 3. 实验设计
*   **数据集/基准测试**：
    *   **SWE-Bench Pro**：跨语言（Python, JS, Java 等）的软件工程基准测试。
    *   **SWE-Bench C#**：内部收集的 150 个 C# 仓库问题，侧重于重型构建和测试任务。
*   **对比方法**：
    *   **无子智能体（Baseline）**：主智能体直接操作终端。
    *   **前沿模型子智能体**：使用 Claude Opus/Sonnet 或 GPT-5.3-Codex 作为子智能体。
    *   **消融版本**：Vanilla Qwen3-4B、仅 SFT 的 4B 模型、以及最终的 Terminus-4B。
*   **评估指标**：解决率（Resolve %）、Token 使用量、主智能体调用终端的频率（衡量对子智能体的信任度）、LLM 裁判评分。

### 4. 资源与算力
*   **算力设备**：训练使用了 **1 个节点，配备 8 张 NVIDIA A100/H100 GPU**。
*   **推理平台**：模型部署在 Fireworks 平台上进行大规模推理评估。
*   **训练时长**：文中未明确给出具体的总训练小时数，但提到 SFT 进行了 2 个 epoch，RL 阶段使用了 16 个 prompt 的 rollout 批次（每步 128 个采样）。

### 5. 实验数量与充分性
*   **实验规模**：实验涵盖了 731 个 SWE-Bench Pro 实例和 150 个 C# 实例，测试了 3 种不同的主智能体模型（GPT、Claude 系列）。
*   **充分性**：研究进行了详尽的消融实验，包括“禁用主智能体终端工具”的极端压力测试，以验证子智能体是否能独立支撑任务。
*   **客观性**：通过多维度 LLM 评分和实际基准测试通过率双重验证，实验设计较为严谨、客观。

### 6. 主要结论与发现
*   **Token 节省**：Terminus-4B 相比无子智能体模式，可减少主智能体约 **30% 的 token 消耗**。
*   **性能持平或超越**：在解决率上，Terminus-4B 达到了与使用 Claude Opus 作为子智能体相当的水平，甚至在某些指标上优于前沿模型。
*   **信任度提升**：经过 RL 训练后，主智能体“重做”子智能体工作的概率显著降低（Subagent → Terminal 指标下降），证明了摘要的有效性。
*   **SLM 的潜力**：证明了针对特定窄域任务（如终端执行），经过强化学习优化的 4B 模型完全可以取代千亿参数模型。

### 7. 优点与亮点
*   **架构实用性**：提出的子智能体模式能直接应用于现有的 AI 编码工具，具有极高的工程实践价值。
*   **创新奖励设计**：通过“执行计划”和多维度评分标准解决了长程智能体任务中奖励稀疏和难以量化的问题。
*   **解耦训练框架**：设计了将子智能体从主循环中解耦的训练流程，大幅降低了 RL 训练时的计算成本。

### 8. 不足与局限
*   **平台覆盖有限**：训练和评估主要集中在 Unix/Bash 环境，未涵盖 Windows PowerShell 或 macOS 专有环境。

*   **评估场景**：虽然在 SWE-Bench 上表现良好，但在更复杂的现实工业环境（如涉及复杂云部署或多机协作）中的表现尚待观察。
