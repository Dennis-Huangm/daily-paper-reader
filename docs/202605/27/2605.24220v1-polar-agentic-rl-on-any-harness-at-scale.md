## 摘要
语言智能体的强化学习越来越依赖于管理长期上下文、多轮工具使用和多智能体编排的自定义测试框架（harnesses）。然而，将这些测试框架移植到强化学习环境接口中仍然很困难，且往往会丢失重要的训练信号。我们通过 Polar 弥补了这一差距，这是一个用于在任意智能体测试框架上进行大规模异步强化学习的采样（rollout）框架。Polar 将智能体测试框架视为黑盒：它代理大语言模型 API 调用，记录 Token 级别的模型交互，并为训练重建 Token 级忠实的轨迹。每个采样节点高效地并行管理运行时预热、智能体执行、轨迹重建和评估，并暴露异步服务终点，供独立训练器大规模调用。这种解耦设计使 Polar 与智能体测试框架、训练基础设施和强化学习算法无关，同时提高了长时间运行的智能体工作负载的计算利用率。我们通过在流行的编程测试框架上训练软件工程任务的智能体来验证 Polar。使用简单的 GRPO，Polar 在 SWE-Bench Verified 基准测试中，配合 Codex、Claude Code、Qwen Code 和 Pi 测试框架，分别将 Qwen3.5-4B 的性能提升了 22.6、4.8、0.6 和 6.2 个百分点。我们进一步展示了 Polar 在自定义测试框架上进行离线数据生成的能力，并对轨迹重建策略进行了消融实验。Polar 重写了其前序工作 Prorl Agent，并已被注册为 NeMo Gym 环境之一。

## Abstract
Reinforcement learning for language agents increasingly depends on custom harnesses that manage long-running context, multi-turn tool use and multi-agent orchestration. However, porting these harnesses into RL environment interfaces remains difficult and often loses important training signals. We bridge this gap with polar, a rollout framework for scalable asynchronous RL over arbitrary agent harnesses. Polar treats the agent harness as a black box: it proxies LLM API calls, records token-level model interactions, and reconstructs token-faithful trajectories for training. Each rollout node efficiently manages runtime prewarming, agent execution, trajectory reconstruction, and evaluation in parallel, exposing asynchronous service endpoints that can be consumed by independent trainers at scale. This decoupled design makes Polar agnostic to agent harnesses, training infrastructure, and RL algorithms while improving compute utilization for long-running agent workloads. We validate polar by training agents on software-engineering tasks with popular coding harnesses. Using simple GRPO, polar improves Qwen3.5-4B by 22.6, 4.8, 0.6 and 6.2 points on SWE-Bench Verified with the Codex, Claude Code, Qwen Code and Pi harnesses, respectively. We further demonstrate Polar for offline data generation over custom harnesses and ablate trajectory reconstruction strategies. Polar rewrites its preceding work, Prorl Agent, and has been registered as one of NeMo Gym environments.

### 1. 核心问题与整体含义
*   **研究动机**：随着大语言模型（LLM）向智能体（Agent）演进，训练过程越来越依赖复杂的测试框架（Harness），这些框架负责管理长上下文、多轮工具调用和多智能体协作。
*   **核心痛点**：传统的强化学习（RL）框架（如 OpenAI Gym）要求将环境逻辑重写为标准接口。然而，现有的智能体框架（如 SWE-bench、Claude Code）逻辑复杂、环境异构，甚至可能是闭源二进制文件，将其适配到 RL 环境中不仅耗时耗力，还容易在数据转换中丢失关键的训练信号（如 Token 级别的概率）。
*   **整体含义**：Polar 提出了一种“黑盒”训练范式，通过代理智能体与模型之间的 API 通信，无需修改任何框架代码即可实现大规模异步强化学习采样。

### 2. 方法论
*   **核心思想**：将集成边界从“智能体框架内部”移动到“模型 API 边界”。只要智能体需要调用 LLM，Polar 就会拦截这些流量。
*   **关键技术细节**：
    *   **模型 API 代理（Model API Proxy）**：在智能体框架和推理服务器之间放置代理，支持 OpenAI、Anthropic、Google 等多种协议。它记录 Prompt、采样 Token、对数概率（Logprobs）和响应。
    *   **异步采样服务化（Rollout-as-a-Service）**：将任务拆分为独立的服务阶段。
        *   **INIT**：准备容器环境（Docker/Apptainer）和依赖。
        *   **READY**：预热运行环境缓冲区。
        *   **RUNNING**：执行智能体原生命令。
        *   **POSTRUN**：重建轨迹、运行评估器、触发训练器回调。
    *   **Token 忠实轨迹重建（Token-faithful Trajectory Reconstruction）**：
        *   **Prefix Merging 算法**：通过前缀匹配将多轮对话合并。关键在于使用 `Loss Mask` 标记：仅对模型实际生成的 Token 计算损失，而对框架插入的中间文本（如工具输出、系统提示词）进行掩码，从而消除“重分词漂移（Retokenization Drift）”问题。

*   **数据集/场景**：专注于软件工程（SWE）任务，使用 **SWE-Bench Verified** 和 **SWE-Gym**。

*   **对比框架（Harnesses）**：对比了四种主流编程智能体框架：**Codex**、**Claude Code**、**Qwen Code** 和 **Pi**。

### 5. 实验数量与充分性
*   **实验组数**：针对 4 种不同的智能体框架分别进行了完整的 GRPO 训练流程。
*   **消融实验**：对比了“逐请求重建（Per Request）”与“前缀合并（Prefix Merging）”两种策略。
*   **充分性与客观性**：实验不仅涵盖了在线 RL 提升，还展示了离线 SFT 数据生成的案例。通过在不同厂商（OpenAI 风格、Anthropic 风格）的框架上取得一致提升，验证了框架的通用性。实验设计考虑了 credit assignment（信用分配）的噪声问题，具有较高的客观性。

### 6. 主要结论与发现
*   **性能大幅提升**：在 Codex 框架下，Qwen3.5-4B 的 Pass@1 从 3.8% 飙升至 **26.4%**（提升 22.6 个点）。这证明了 Polar 能让模型快速适应陌生的工具调用协议和提示词风格。
*   **计算效率优化**：采用 `Prefix Merging` 策略后，训练速度提升了 **5.39 倍**，GPU 利用率从 20.4% 提高到 **87.7%**。
*   **黑盒训练可行性**：证明了无需理解智能体内部的规划和工具管理逻辑，仅通过 API 流量即可训练出高性能的智能体策略。

### 7. 优点
*   **极低侵入性**：对现有工程生态极其友好，支持任何能通过命令行运行的智能体。
*   **数据高保真**：解决了智能体 RL 中最头疼的 Token 对齐和 Logprobs 丢失问题。
*   **架构解耦**：采样、推理和训练完全分离，能够应对智能体任务中常见的“长尾”执行时间（部分任务可能运行数十分钟）。

### 8. 不足与局限
*   **协议覆盖限制**：虽然支持主流 API，但若智能体使用完全私有的通信协议或非文本交互（如 GUI 像素流且不通过标准 API），则难以直接应用。
*   **奖励稀疏性**：目前主要依赖最终结果奖励（Outcome Reward），对于极其复杂的长程任务，如何通过 Polar 自动提取中间过程奖励（Process Reward）仍有待深入探索。
*   **系统复杂性**：引入了代理层和多级异步队列，增加了系统部署和运维的复杂度。
