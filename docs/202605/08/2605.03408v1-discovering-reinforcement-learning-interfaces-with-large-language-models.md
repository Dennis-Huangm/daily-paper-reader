## 摘要
强化学习系统依赖于指定观测和奖励函数的环境接口，然而为新任务构建这些接口通常需要大量的人工努力。虽然最近的工作已经利用大语言模型（LLMs）实现了奖励设计的自动化，但这些方法假设观测是固定的，并未解决合成完整任务接口这一更广泛的挑战。我们研究了从原始模拟器状态中发现强化学习任务接口的问题，其中必须同时生成观测映射和奖励函数。我们提出了 LIMEN（代码见 https://github.com/Lossfunk/LIMEN），这是一个由 LLM 引导的进化框架，它将候选接口生成为可执行程序，并利用策略训练反馈对其进行迭代优化。在涵盖运动和操纵的新型离散网格世界任务和连续控制领域中，仅给定轨迹级的成功指标，观测和奖励的联合进化就能发现有效的接口，而仅优化其中任何一个组件在至少一个领域中都会失败。这些结果表明，从原始状态自动构建强化学习接口可以显著减少人工工程量，且观测和奖励组件通常受益于协同设计，因为在我们的评估套件中，单组件优化在至少一个领域中会出现灾难性的失败。

## Abstract
Reinforcement learning systems rely on environment interfaces that specify observations and reward functions, yet constructing these interfaces for new tasks often requires substantial manual effort. While recent work has automated reward design using large language models (LLMs), these approaches assume fixed observations and do not address the broader challenge of synthesizing complete task interfaces. We study RL task interface discovery from raw simulator state, where both observation mappings and reward functions must be generated. We propose LIMEN (Code available at https://github.com/Lossfunk/LIMEN), a LLM guided evolutionary framework that produces candidate interfaces as executable programs and iteratively refines them using policy training feedback. Across novel discrete gridworld tasks and continuous control domains spanning locomotion and manipulation, joint evolution of observations and rewards discovers effective interfaces given only a trajectory-level success metric, while optimizing either component alone fails on at least one domain. These results demonstrate that automatic construction of RL interfaces from raw state can substantially reduce manual engineering and that observation and reward components often benefit from co-design, as single-component optimization fails catastrophically on at least one domain in our evaluation suite.

### 2. 方法论：LIMEN 框架
论文提出了 **LIMEN**（Learning Interfaces via MDP-guided EvolutioN），其核心思想是将接口发现视为程序合成问题，并利用进化算法进行优化。

    *   **外层循环（进化）：** LLM（如 Claude 3.5 Sonnet）作为变异算子，根据任务描述、父代代码及训练反馈生成新的接口程序。
    *   **内层循环（评估）：** 使用生成的接口训练 RL 智能体（如 PPO），以轨迹级的“成功率”作为适应度（Fitness）信号。
*   **关键技术：**
    *   **级联过滤（Cascade Filter）：** 先进行短时间的训练评估，剔除无效接口，节省算力。
    *   **多样性存档：** 根据观测维度和奖励代码复杂度将接口分类存储，防止搜索陷入局部最优。
    *   **反馈闭环：** 将训练中的错误回溯、性能指标反馈给 LLM，指导其进行更有针对性的代码修改。

### 6. 主要结论与发现
*   **联合优化的必要性：** 观测和奖励具有强耦合性。在网格世界中，瓶颈在于观测（Reward-only 失败）；在机器人任务中，瓶颈在于奖励（Obs-only 失败）。只有 LIMEN 这种联合进化方法在所有任务中均未出现灾难性失败。
*   **性能提升：** LIMEN 在所有任务上的成功率均显著高于基准方法，尤其在 Hard 任务中，从 Sparse 的 1% 提升到了 85%。
*   **鲁棒性：** 发现的接口在环境动力学发生偏移（如推力加倍、速度加快）时，仍能保持非零的成功率，展现了一定的泛化能力。
*   **可解释性：** LLM 生成的程序展现了类似人类专家的设计模式，如构造相对坐标、距离归一化、势能奖励（Potential-based rewards）等。

### 7. 优点与亮点
*   **端到端自动化：** 首次实现了从原始模拟器状态到完整 MDP 接口（观测+奖励）的自动化程序合成。
*   **程序化表示：** 生成的是 Python 代码而非黑盒神经网络，具有极高的**可解释性**和**可移植性**。
*   **效率优化：** 通过 JAX 并行化和级联过滤机制，解决了“进化套强化”带来的巨大计算开销问题。

### 8. 不足与局限
*   **依赖特权信息：** 目前框架假设 LLM 可以访问模拟器的结构化状态变量（如坐标、速度），在处理纯像素输入（Vision-based）的任务时尚不直接适用。
*   **计算成本：** 尽管有优化，但每个新任务仍需数小时的 GPU 训练，对于超大规模环境的扩展性仍具挑战。
*   **适应度信号依赖：** 算法仍需要一个预定义的“成功指标”来引导进化，如果任务本身难以定义成功（如开放式探索），则难以应用。
*   **搜索空间限制：** 观测维度被限制在 512 维以内，且程序复杂度受限于 LLM 的上下文长度和生成能力。
