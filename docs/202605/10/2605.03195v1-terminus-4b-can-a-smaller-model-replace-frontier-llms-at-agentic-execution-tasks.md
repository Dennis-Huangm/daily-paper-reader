## 摘要
现代编程智能体越来越多地将专门的子任务委托给子智能体，即处理搜索、调试或终端执行等特定职责的小型、专注的智能体循环。这种架构模式通过将冗长的输出（如构建日志、测试结果等）隔离在子智能体上下文中，从而保持主智能体的上下文窗口整洁。通常，当智能体为此类任务使用子智能体时，会采用前沿模型。在本文中，我们研究了经过微调的小语言模型（SLM）在智能体终端执行任务中是否能达到与前沿模型相当的性能。我们提出了 Terminus-4B，这是一个专门针对该任务，通过监督微调（SFT）和使用基于评分标准的 LLM-as-judge 奖励的强化学习（RL）进行后期训练的 Qwen3-4B 模型。在涵盖各种前沿模型、训练消融实验和主智能体配置的广泛评估中，我们发现，与无子智能体基准相比，Terminus-4B 能够将主智能体的 token 使用量减少高达约 30%，且不会影响在 SWE-Bench Pro 和我们内部的 SWE-Bench C# 基准测试（该基准测试通常包含大量冗长的执行任务）上的性能。此外，Terminus-4B 改进了关键指标，表明主智能体更多地依赖子智能体的输出，并减少了自身执行终端任务的次数。我们观察到，我们的模型不仅缩小了原始 Qwen 模型与 Claude Sonnet / Opus / GPT-5.3-Codex 等前沿模型之间的差距，甚至往往能超越它们的表现。

## Abstract
Modern coding agents increasingly delegate specialized subtasks to subagents, which are smaller, focused agentic loops that handle narrow responsibilities like search, debugging or terminal execution. This architectural pattern keeps the main agent's context window clean by isolating verbose outputs (e.g. build logs, test results, etc.) within the subagent context. Typically when agents employ subagents for such tasks, they use frontier models as these subagents. In this paper, we investigate whether a finetuned small language model (SLM) can achieve comparable performance to frontier models in the task of agentic terminal execution. We present Terminus-4B, which is a post-trained Qwen3-4B model via Supervised Finetuning (SFT) and Reinforcement Learning (RL) using rubric-based LLM-as-judge reward, specifically for this task. In our extensive evaluation spanning various frontier models, training ablations and main agent configurations, we find that Terminus-4B is able to reduce the token usage of the main agent by up to ~30% compared to the No Subagent baseline with no impact to agent performance on benchmarks like SWE-Bench Pro and our internal SWE-Bench C# benchmark, which tends to be heavy in verbose execution tasks. Furthermore, Terminus-4B improves key metrics showing the main agent relying on the outputs of the subagent and doing fewer terminal execution tasks by itself. We see that our model not only closes the gap between the Vanilla Qwen model and frontier models like Claude Sonnet / Opus / GPT-5.3-Codex, but often even exceeds their performance.

*   **核心痛点**：现代编程智能体在解决 GitHub 问题时，需要频繁运行构建、安装依赖和执行测试。这些终端输出（如编译日志、测试报告）极其冗长，往往会迅速填满主智能体的上下文窗口（Context Window），导致推理能力下降、成本激增，并挤占了关键的代码逻辑和规划空间。
*   **研究动机**：作者提出将“终端执行”这一特定任务委托给一个专门的“子智能体”（Subagent）。虽然目前通常使用 Claude 或 GPT 等前沿大模型（Frontier LLMs）充当子智能体，但作者认为这种做法大材小用。
*   **核心目标**：验证一个经过针对性训练的 4B 参数小模型，是否能在终端执行任务中达到甚至超越前沿大模型的表现，从而实现降本增效。

### 2. 方法论
*   **核心思想**：采用“主智能体-子智能体”架构。主智能体仅发送自然语言指令（如“运行测试并报告错误”），子智能体在独立循环中执行命令，最后仅返回结构化的 XML 摘要（`<final_answer>`），从而为主智能体屏蔽冗长的原始输出。
*   **关键技术细节**：
    *   **两阶段后训练**：
        1.  **SFT（有监督微调）**：使用从生产环境遥测数据中提取的专家轨迹（约 3200 个任务）对 Qwen3-4B 进行微调，使其掌握工具调用和摘要格式。
        2.  **RL（强化学习）**：采用 **GRPO**（群组相对策略优化）算法。
    *   **解耦式 Rollout 框架**：为了降低训练成本，在 RL 阶段将子智能体与昂贵的主智能体解耦，使用轻量级模型模拟主智能体发送指令。
    *   **基于评分标准的奖励设计（Rubric-based Reward）**：
        *   由于终端任务没有简单的二元对错，作者引入了 **LLM-as-judge**。
        *   将原始轨迹转化为“执行计划”（Execution Plan），由前沿模型根据 14 个维度（执行质量、失败模式、最终答案质量）进行打分。
        *   奖励公式：$r = (1 - \alpha)(\bar{s}_{pos} - \bar{s}_{pit}) + \alpha \cdot \bar{s}_{fa}$，平衡了执行过程的正确性与最终摘要的有用性。

### 3. 实验设计
*   **数据集 / 基准测试**：
    *   **SWE-Bench Pro**：多语言基准测试（Python, JS, Java, Go 等），用于测试跨语言泛化能力。
    *   **SWE-Bench C#**：内部构建的针对 C# 语言的基准测试，包含大量重度执行任务。
*   **对比方法**：
    *   **基准线**：无子智能体（主智能体直接操作终端）。
    *   **前沿模型子智能体**：使用 Claude Opus 4.6、Claude Sonnet 4.5、GPT-5.3-Codex 作为子智能体。
    *   **消融版本**：原始 Qwen3-4B（Vanilla）、仅经过 SFT 的版本（SFT-4B）。
*   **评估指标**：解决率（Resolve %）、Token 使用量、主智能体对终端的直接调用次数、以及“不信任信号”（即主智能体在子智能体运行后是否又亲自重跑命令）。

### 4. 资源与算力
*   **训练算力**：使用了 **1 台包含 8 块 NVIDIA A100/H100 GPU 的节点**。
*   **推理平台**：部署在 Fireworks AI 平台上进行快速推理。
*   **训练时长**：SFT 阶段进行了 2 个 Epoch；RL 阶段的具体时长未明确说明，但提到了每步采样 128 条轨迹（16 个 Prompt $\times$ 8 个样本）。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 731 个 SWE-Bench Pro 实例和 150 个 C# 实例。
*   **充分性**：实验设计非常全面。作者不仅测试了不同的小模型版本，还更换了不同的主智能体（Claude 和 GPT 系列）以验证子智能体的通用性。
*   **消融实验**：特别设计了“移除终端工具”的压力测试，强制主智能体完全依赖子智能体，从而更客观地衡量小模型的独立工作能力。

### 6. 主要结论与发现
*   **Token 节省**：Terminus-4B 成功将主智能体的 Token 消耗降低了 **约 30%**，显著降低了运行成本。
*   **性能持平/超越**：在解决率上，Terminus-4B 达到了与 Claude Opus 充当子智能体相当的水平，甚至在某些指标上优于前沿模型。
*   **RL 的必要性**：实验显示，仅靠 SFT 无法让小模型达到前沿模型的水平，RL 阶段对于减少“幻觉”和提升摘要的“可操作性”至关重要。
*   **行为改变**：主智能体表现出对 Terminus-4B 的高度信任，直接调用终端的次数减少了 70% 以上。

### 7. 优点
*   **架构实用性**：针对工业界智能体落地的痛点（成本和上下文限制）提出了切实可行的方案。
*   **训练创新**：提出的“执行计划摘要”比对方法，解决了长轨迹 RL 训练中奖励计算昂贵且稀疏的问题。
*   **高效性**：证明了 4B 规模的模型通过精细化的后训练，可以在特定垂直领域（终端执行）替代千亿级参数的大模型。

### 8. 不足与局限
*   **平台覆盖有限**：训练和评估主要集中在 Unix/Bash 环境，未涵盖 Windows (PowerShell) 或 Mac (Zsh) 的特有任务。
*   **评估场景单一**：主要基于 SWE-Bench 风格的 Docker 容器环境，现实中更复杂的部署或基础设施任务可能更具挑战性。
*   **模型选择偏差**：仅在 Qwen3 系列上进行了验证，尚不清楚该训练配方是否能完美迁移到 Llama 或 Mistral 等其他模型家族。
