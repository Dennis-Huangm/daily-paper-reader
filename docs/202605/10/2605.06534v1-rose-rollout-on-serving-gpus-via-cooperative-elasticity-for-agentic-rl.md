## 摘要
智能体强化学习（Agentic RL）已成为提升大语言模型（LLM）多步推理和工具使用能力的关键驱动力。然而，其效率受限于具有多轮环境交互的长尾 Rollout，使得静态 GPU 配置难以适配：过度配置会在落后者（stragglers）上浪费 GPU 资源，而配置不足则会增加竞争并减慢训练速度。我们观察到，生产环境中的推理服务集群通常会留有大量的 GPU 计算和显存余量。基于这一观察，我们提出了协作弹性（cooperative elasticity）：机会性地重新利用未充分利用的推理服务 GPU 来执行 Rollout。实现协作弹性并非易事，因为它必须在突发流量下维持推理服务的服务水平目标（SLO），并最小化通信开销。为了应对这些挑战，我们提出了 ROSE，这是一个协作式资源弹性后训练系统，它能安全地利用推理服务 GPU 上的空闲计算和显存资源，以加速智能体强化学习的 Rollout。ROSE 由三个组件组成：(1) 一个 SLO 安全的共存服务执行器，通过高效的 GPU 显存和计算共享，在保持推理服务 SLO 的同时提高 Rollout 吞吐量；(2) 一个跨集群权重传输引擎，利用权重分片和稀疏性实现跨集群的快速权重同步；(3) 一个弹性 Rollout 调度器，动态配置协作容量，并在专用 Rollout GPU 和机会性推理服务 GPU 之间路由轨迹 Rollout。在多种模型大小和集群规模上的实验表明，与最先进的资源固定和弹性基准相比，ROSE 将平均端到端吞吐量提高了 1.20-3.31 倍。

## Abstract
Agentic reinforcement learning (RL) has emerged as a key driver for improving the multi-step reasoning and tool-use capabilities of LLMs. However, its efficiency is bottlenecked by long-tail rollouts with multi-turn environment interactions, making static GPU provisioning a poor fit: overprovisioning wastes GPUs on stragglers, while underprovisioning increases contention and slows training.   We observe that production serving clusters routinely leave substantial GPU compute and memory headroom. Based on this observation, we argue for cooperative elasticity: opportunistically repurposing underutilized serving GPUs to execute rollouts. Realizing cooperative elasticity is non-trivial because it must preserve serving Service Level Objectives (SLOs) under bursty traffic and minimize communication overhead. To address these challenges, we present ROSE, a cooperative, resource-elastic post-training system that safely harvests idle compute and memory on serving GPUs to accelerate agentic RL rollouts. ROSE consists of three components: (1) an SLO-safe co-serving executor that improves rollout throughput while preserving serving SLOs through efficient GPU memory and compute sharing; (2) a cross-cluster weight transfer engine that leverages weight shards and sparsity for fast weight synchronization across clusters; and (3) an elastic rollout scheduler that dynamically provisions cooperative capacity and routes trajectory rollouts across dedicated rollout GPUs and opportunistic serving GPUs. Experiments across multiple model sizes and cluster scales show that ROSE improves average end-to-end throughput by 1.20-3.31 x compared with state-of-the-art resource-fixed and elastic baselines.

*   **核心问题**：智能体强化学习（Agentic RL）在提升大语言模型（LLM）的多步推理和工具使用能力方面至关重要，但其效率受限于**长尾 Rollout**（环境交互阶段）。Rollout 占据了超过 70% 的训练时间，且由于多轮交互的复杂性，其资源需求波动巨大。
*   **研究背景**：传统的静态资源分配（固定 GPU 数量）会导致资源浪费（等待长尾任务）或严重竞争（资源不足）。与此同时，企业内部的大规模推理服务集群（Serving Cluster）通常存在显著的计算和显存余量（SM 利用率仅约 18.9%）。
*   **整体含义**：论文提出了**协作弹性（Cooperative Elasticity）**的概念，即在保障推理服务质量（SLO）的前提下，动态“窃取”推理集群的空闲资源来加速 RL 的 Rollout 过程。

#### 2. 方法论：核心思想与关键技术
ROSE 系统由三个核心组件构成：
*   **SLO 安全的共存服务执行器（Co-serving Executor）**：
    *   **显存共享**：利用 CUDA VMM（虚拟内存管理）实现异构模型间的显存动态重平衡，无需重启进程即可调整 KV Cache 大小。
    *   **抢占式内存策略**：保留 Rollout 的前缀缓存（Prefix Caching）以加速推理，但在推理服务流量激增时，通过“紧急削减”机制强制回收显存。
    *   **双 SLO 准入控制**：实时监控推理服务的首字延迟（TTFT）和单字延迟（TPOT）余量，仅在不违反 SLO 的前提下插入 Rollout 计算任务。
*   **跨集群权重传输引擎（Weight Transfer Engine）**：
    *   **异步与分片感知**：支持训练与推理集群间不同并行策略（如 TP/PP）的自动映射。
    *   **稀疏性感知**：发现 RL 训练中相邻步骤的权重增量（Delta）具有 **>95% 的无损稀疏性**，通过仅传输非零增量，将跨集群同步时间缩短至 20 秒以内。
*   **弹性 Rollout 调度器（Rollout Scheduler）**：
    *   **轮次级路由**：在多轮交互的每一轮动态决定是在专用 GPU 还是借用的推理 GPU 上执行。
    *   **缓存亲和性放置**：优先将任务分配给持有该轨迹 KV Cache 的 GPU，以最大化前缀复用。

#### 8. 不足与局限
*   **模型异构性限制**：虽然支持异构模型，但如果推理模型和 Rollout 模型规模差异过大（如 1.5B 与 70B 共存），显存碎片和计算干扰可能仍难以完全消除。

*   **极端流量风险**：在推理服务遭遇极端突发流量（如全集群并发激增）时，Rollout 任务仍会被大面积抢占，导致训练进度出现瞬时停滞。
