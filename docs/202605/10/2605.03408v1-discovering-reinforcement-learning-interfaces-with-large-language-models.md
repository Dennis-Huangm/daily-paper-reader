## Abstract
Reinforcement learning systems rely on environment interfaces that specify observations and reward functions, yet constructing these interfaces for new tasks often requires substantial manual effort. While recent work has automated reward design using large language models (LLMs), these approaches assume fixed observations and do not address the broader challenge of synthesizing complete task interfaces. We study RL task interface discovery from raw simulator state, where both observation mappings and reward functions must be generated. We propose LIMEN (Code available at https://github.com/Lossfunk/LIMEN), a LLM guided evolutionary framework that produces candidate interfaces as executable programs and iteratively refines them using policy training feedback. Across novel discrete gridworld tasks and continuous control domains spanning locomotion and manipulation, joint evolution of observations and rewards discovers effective interfaces given only a trajectory-level success metric, while optimizing either component alone fails on at least one domain. These results demonstrate that automatic construction of RL interfaces from raw state can substantially reduce manual engineering and that observation and reward components often benefit from co-design, as single-component optimization fails catastrophically on at least one domain in our evaluation suite.

### 1. 核心问题与整体含义
*   **研究动机**：强化学习的效果高度依赖于“接口”设计，即智能体观察到什么（观测映射 $\phi$）以及如何获得奖励（奖励函数 $R$）。目前，人工设计这些组件是RL应用中的主要瓶颈。
*   **核心问题**：虽然已有研究（如 Eureka）实现了奖励函数的自动化设计，但它们通常假设观测空间是固定且优化过的。在原始模拟器状态（Raw State）杂乱无章的情况下，仅优化奖励往往不足以让智能体学会复杂任务。
*   **整体含义**：论文提出了 **LIMEN** 框架，旨在从原始模拟器状态出发，**同时自动合成**可执行的观测程序和奖励程序，实现 MDP（马尔可夫决策过程）接口的端到端发现。

### 2. 方法论
*   **核心思想**：将接口发现视为一个在可执行 Python 程序空间中的进化搜索问题，利用 LLM 作为变异算子，并通过实际的 RL 策略训练效果作为反馈信号。
*   **关键技术细节**：
    *   **接口表示**：观测和奖励均表示为 Python 函数，使用 JAX 兼容的数值运算，直接操作模拟器的原始变量。
    *   **LIMEN 框架**：采用 **MAP-Elites**（一种质量-多样性进化算法）维护一个接口存档。存档根据“观测维度”和“奖励结构复杂度”两个维度进行分箱，以保持种群多样性。
    *   **LLM 引导进化**：使用 LLM（如 Claude 3.5 Sonnet）根据任务描述、父代代码、训练反馈（成功率、错误日志）生成新的候选接口。
    *   **双层优化**：外层循环进化接口程序，内层循环使用 PPO 算法训练智能体以评估该接口的“适应度”（Fitness，即任务成功率）。
    *   **级联评估（Cascade Filter）**：为了节省算力，先进行短时间的训练筛选，只有表现达标的接口才会进入完整的多随机种子评估。

### 3. 实验设计
*   **实验场景**：
    1.  **XLand-MiniGrid**：离散网格世界任务，包括简单（拾取）、中等（关系放置）、困难（多步骤规则链）。
    2.  **MuJoCo (MJX)**：连续控制任务，包括 Go1 四足机器人推力恢复和 Panda 机械臂轨迹跟踪。
*   **对比方法（Baselines）**：
    *   **Sparse**：原始观测 + 简单的二元成功奖励。
    *   **Obs-Only**：仅进化观测映射，奖励固定。
    *   **Reward-Only**：仅进化奖励函数，观测固定（类似于 Eureka/Text2Reward）。
    *   **独立 LLM 采样**：不使用进化算法，直接让 LLM 随机生成 30 个接口。
*   **鲁棒性测试**：在动力学扰动（如增加推力、改变速度）下测试进化出的接口是否依然有效。

### 4. 资源与算力
*   **硬件**：所有实验均在单张 **NVIDIA L4 GPU** 上运行。
*   **时长**：
    *   XLand 任务：每次进化运行约 1-3 小时。
    *   MuJoCo 任务：每次进化运行约 6-7 小时。
    *   总计墙钟时间约 36.1 小时。
*   **LLM 成本**：使用 Claude 3.5 Sonnet，总计消耗约 920 万 Token，API 费用约为 **42.10 美元**。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 5 种不同性质的任务（离散 vs 连续，推理 vs 控制）。
*   **充分性**：
    *   每组进化运行包含 30 次迭代。
    *   最终评估使用了 10 个独立随机种子，以消除进化过程中的噪声。
    *   进行了详细的消融实验（Obs-only 和 Reward-only），证明了联合优化的必要性。
    *   **客观性**：通过对比“独立采样”基准，客观证明了进化闭环（反馈学习）的价值。

### 6. 主要结论与发现
*   **联合优化的必要性**：在复杂任务中，单一组件优化往往会失败。例如，在机械臂任务中 Obs-only 失败，而在网格世界困难任务中 Reward-only 失败。只有 LIMEN（联合进化）在所有任务中均表现稳健。
*   **设计模式的涌现**：进化出的接口展现了人类专家的设计倾向，如：观测程序会自动计算相对距离、方向向量和任务阶段标识；奖励程序会自动加入势能函数（Potential-based shaping）和阶段性奖励。
*   **进化优于零射（Zero-shot）**：即使是 LLM 随机采样的最佳结果也远逊于进化后的接口，说明迭代反馈对于导航复杂的程序空间至关重要。

### 7. 优点
*   **端到端自动化**：首次实现了从原始状态到完整 MDP 接口的自动化合成，极大减少了人工调参。
*   **可解释性**：输出的是 Python 代码，而非黑盒嵌入，方便研究人员理解和验证。
*   **计算效率**：通过 JAX 并行模拟和级联过滤机制，在有限的算力资源下完成了复杂的进化搜索。

### 8. 不足与局限
*   **依赖特权信息**：目前假设可以访问模拟器的结构化状态变量（如坐标、速度），而非原始像素输入。
*   **算力开销**：虽然使用了 JAX，但内层循环的 RL 训练依然耗时，扩展到更大规模环境（如视觉输入）可能面临挑战。
*   **成功指标依赖**：仍需人工提供一个高层级的“成功判定标准”作为进化引导。
*   **观测膨胀**：LLM 倾向于生成冗余的观测特征，未来可能需要引入观测维度的惩罚项。
