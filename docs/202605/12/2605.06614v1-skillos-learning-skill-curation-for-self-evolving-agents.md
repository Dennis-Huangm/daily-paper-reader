## 摘要
基于大语言模型（LLM）的智能体越来越多地被部署用于处理流式任务，但它们通常仍是单次问题解决者，无法从过去的交互中学习。从经验中提炼出的可重用技能为自我进化提供了天然基础，而高质量的技能管理（skill curation）则是其中的关键瓶颈。现有方法要么依赖手动技能管理，要么规定启发式技能操作，或者针对短时程技能操作进行训练。然而，它们仍然难以从间接且延迟的反馈中学习复杂的长期管理策略。为了应对这一挑战，我们提出了 SkillOS，这是一种经验驱动的强化学习（RL）训练方案，用于在自我进化智能体中学习技能管理。SkillOS 将一个负责检索和应用技能的冻结智能体执行器与一个可训练的技能管理器配对，后者根据积累的经验更新外部技能库（SkillRepo）。为了提供管理的学习信号，我们设计了复合奖励，并在基于技能相关任务依赖的分组任务流上进行训练，其中早期的轨迹用于更新 SkillRepo，而随后的相关任务则用于评估这些更新。在多轮智能体任务和单轮推理任务中，SkillOS 在有效性和效率方面均持续优于无记忆和强记忆基线，且学习到的技能管理器能够跨不同的执行器骨干和任务领域进行泛化。进一步的分析表明，学习到的管理器能产生更有针对性的技能使用，而 SkillRepo 中的技能随着时间的推移演变成结构更丰富的 Markdown 文件，编码了更高层级的元技能。

## Abstract
LLM-based agents are increasingly deployed to handle streaming tasks, yet they often remain one-off problem solvers that fail to learn from past interactions. Reusable skills distilled from experience provide a natural substrate for self-evolution, where high-quality skill curation serves as the key bottleneck. Existing approaches either rely on manual skill curation, prescribe heuristic skill operations, or train for short-horizon skill operations. However, they still struggle to learn complex long-term curation policies from indirect and delayed feedback. To tackle this challenge, we propose SkillOS, an experience-driven RL training recipe for learning skill curation in self-evolving agents. SkillOS pairs a frozen agent executor that retrieves and applies skills with a trainable skill curator that updates an external SkillRepo from accumulated experience. To provide learning signals for curation, we design composite rewards and train on grouped task streams based on skill-relevant task dependencies, where earlier trajectories update the SkillRepo, and later related tasks evaluate these updates. Across multi-turn agentic tasks and single-turn reasoning tasks, SkillOS consistently outperforms memory-free and strong memory-based baselines in both effectiveness and efficiency, with the learned skill curator generalizing across different executor backbones and task domains. Further analyses show that the learned curator produces more targeted skill use, while the skills in SkillRepo evolve into more richly structured Markdown files that encode higher-level meta-skills over time.

### SkillOS: 面向自我进化智能体的技能管理学习论文总结

#### 1. 核心问题与整体含义
论文针对当前大语言模型（LLM）智能体大多为“一次性”问题解决者、无法从过去交互中积累经验的局限性，提出了**自我进化（Self-Evolution）**的概念。研究的核心瓶颈在于**技能管理（Skill Curation）**：如何从原始执行轨迹中自动提取高质量、可重用的技能，并对其进行动态更新或删除。现有方法多依赖手动规则或简单的启发式逻辑，难以应对长期任务流中的复杂决策和延迟反馈。

#### 2. 方法论
SkillOS 采用了一种模块化的多智能体设计，核心思想是将“执行”与“管理”分离：
*   **模块化架构**：
    *   **智能体执行器（Agent Executor）**：保持冻结（Frozen），负责从技能库（SkillRepo）检索技能并执行任务。
    *   **技能管理器（Skill Curator）**：可训练的策略模型（基于 Qwen3-8B），通过函数调用（插入、更新、删除）管理以 Markdown 格式存储的技能。
*   **关键技术细节**：
    *   **分组任务流训练（Grouped Task Streams）**：将具有技能依赖关系的相关任务编组。管理器在处理组内早期任务时更新技能库，其效果由后续相关任务的执行表现来评估，从而解决反馈延迟问题。
    *   **复合奖励函数**：结合了任务结果奖励（下游执行成功率）、函数调用规范奖励、内容质量奖励（由外部模型评分）和压缩奖励（鼓励精简而非直接复制轨迹）。
    *   **优化算法**：使用 **GRPO（Grouped Reward Policy Optimization）** 算法进行强化学习训练，以提高训练稳定性和样本效率。

#### 3. 实验设计
*   **实验场景与数据集**：
    *   **多轮智能体任务**：ALFWorld（具身智能家居任务）、WebShop（在线购物模拟）。
    *   **单轮推理任务**：AIME24、AIME25、GPQA-Diamond（高难度数学与科学推理）。
*   **基线方法（Benchmarks）**：
    *   **无记忆（No Memory）**：独立解决每个任务。
    *   **强记忆基线**：ReasoningBank（提炼推理见解）、MemP（启发式程序化记忆管理）。
    *   **内部变体**：SkillOS-base（未经过 RL 训练的管理器）、SkillOS-gemini（直接使用 Gemini-2.5-Pro 作为管理器）。
*   **评估维度**：有效性（成功率/准确率）与效率（执行步数/Token 消耗）。

#### 4. 资源与算力
论文明确说明了算力使用情况：
*   **硬件**：使用 **16 张 NVIDIA H100 GPU**。
*   **训练时长**：ALFWorld 约 3 天，推理任务约 2.5 天，WebShop 约 5 天。
*   **框架**：基于 `verl` 强化学习框架进行训练。

#### 5. 实验数量与充分性
实验设计非常充分且具有客观性：
*   **多维度验证**：涵盖了从具身交互到抽象推理的不同领域。
*   **泛化性测试**：验证了 8B 规模的管理器在不同执行器（Qwen3-8B/32B、Gemini-2.5-Pro、Gemini-3.1-Flash-Lite）上的表现，证明了其跨模型兼容性。
*   **消融实验**：对奖励组成部分和任务分组策略进行了详细消融，验证了各设计的必要性。
*   **演化分析**：深入分析了技能库随训练时间的变化，展示了从简单指令到复杂元策略的演化过程。

#### 6. 主要结论与发现
*   **性能卓越**：SkillOS 在所有基准测试中均显著优于无记忆和现有的记忆管理方法。
*   **效率提升**：在提升成功率的同时，显著减少了智能体完成任务所需的交互步数。
*   **小模型逆袭**：经过 RL 训练的 8B 管理器在技能管理任务上甚至超过了未针对该任务优化的顶级模型（如 Gemini-2.5-Pro）。
*   **元技能涌现**：随着训练进行，管理器学会了从关注特定任务细节转向提取更高级的策略（如失败恢复、系统性搜索等）。

#### 7. 优点
*   **解耦设计**：执行器与管理器分离，使得系统非常灵活，无需重新训练昂贵的执行器即可实现进化。
*   **经验驱动**：通过 RL 直接优化管理策略，而非依赖人工定义的启发式规则。
*   **泛化能力强**：训练出的管理器具有良好的跨领域和跨模型迁移能力。
*   **可解释性**：技能以 Markdown 形式存储，易于人类阅读、审计和手动干预。

#### 8. 不足与局限
*   **检索机制简单**：目前依赖 BM25 关键词检索，对于语义关联极强但关键词不匹配的技能可能检索不到。
*   **技能表示简化**：目前将技能简化为单个 Markdown 文件，不支持更复杂的脚本或多文件层级结构。
*   **执行器冻结限制**：虽然解耦是优点，但也意味着管理器必须单方面适应执行器的“脾气”，无法通过联合优化达到最优协同。
*   **训练成本**：强化学习训练过程（尤其是涉及多轮交互时）对算力和时间的要求仍然较高。
