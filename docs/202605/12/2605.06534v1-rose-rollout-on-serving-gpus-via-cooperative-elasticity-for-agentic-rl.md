## 摘要
智能体强化学习（Agentic RL）已成为提升大语言模型（LLM）多步推理和工具使用能力的关键驱动力。然而，其效率受限于具有多轮环境交互的长尾 Rollout，使得静态 GPU 资源配置难以适配：过度配置会在落后者（stragglers）上浪费 GPU 资源，而配置不足则会增加竞争并减慢训练速度。我们观察到，生产环境中的推理服务集群通常留有大量的 GPU 计算和显存余量。基于这一观察，我们提出了协作弹性（cooperative elasticity）：机会性地重新利用未充分利用的推理服务 GPU 来执行 Rollout。实现协作弹性并非易事，因为它必须在突发流量下维持推理服务的服务水平目标（SLO），并最小化通信开销。为了应对这些挑战，我们提出了 ROSE，这是一个协作式、资源弹性的后训练系统，它能安全地利用推理服务 GPU 上的空闲计算和显存资源，以加速 Agentic RL 的 Rollout。ROSE 由三个组件组成：（1）一个 SLO 安全的共存服务执行器，通过高效的 GPU 显存和计算共享，在保持推理服务 SLO 的同时提高 Rollout 吞吐量；（2）一个跨集群权重传输引擎，利用权重分片和稀疏性实现集群间的快速权重同步；（3）一个弹性 Rollout 调度器，动态配置协作容量，并在专用 Rollout GPU 和机会性推理服务 GPU 之间路由轨迹 Rollout。在多种模型规模和集群规模下的实验表明，与最先进的资源固定和弹性基准相比，ROSE 将平均端到端吞吐量提高了 1.20-3.31 倍。

## Abstract
Agentic reinforcement learning (RL) has emerged as a key driver for improving the multi-step reasoning and tool-use capabilities of LLMs. However, its efficiency is bottlenecked by long-tail rollouts with multi-turn environment interactions, making static GPU provisioning a poor fit: overprovisioning wastes GPUs on stragglers, while underprovisioning increases contention and slows training.   We observe that production serving clusters routinely leave substantial GPU compute and memory headroom. Based on this observation, we argue for cooperative elasticity: opportunistically repurposing underutilized serving GPUs to execute rollouts. Realizing cooperative elasticity is non-trivial because it must preserve serving Service Level Objectives (SLOs) under bursty traffic and minimize communication overhead. To address these challenges, we present ROSE, a cooperative, resource-elastic post-training system that safely harvests idle compute and memory on serving GPUs to accelerate agentic RL rollouts. ROSE consists of three components: (1) an SLO-safe co-serving executor that improves rollout throughput while preserving serving SLOs through efficient GPU memory and compute sharing; (2) a cross-cluster weight transfer engine that leverages weight shards and sparsity for fast weight synchronization across clusters; and (3) an elastic rollout scheduler that dynamically provisions cooperative capacity and routes trajectory rollouts across dedicated rollout GPUs and opportunistic serving GPUs. Experiments across multiple model sizes and cluster scales show that ROSE improves average end-to-end throughput by 1.20-3.31 x compared with state-of-the-art resource-fixed and elastic baselines.

### 论文总结：ROSE —— 通过协作弹性在推理服务 GPU 上实现智能体强化学习的 Rollout

#### 1. 核心问题与整体含义（研究动机和背景）
智能体强化学习（Agentic RL）通过多轮环境交互提升大语言模型（LLM）的推理和工具使用能力。然而，其效率面临两大瓶颈：
*   **Rollout 占据主导地位：** Rollout 阶段（模型与环境交互生成轨迹）通常占总训练时间的 70% 以上。
*   **长尾效应与资源错配：** 轨迹长度分布极不均匀，静态分配 GPU 资源会导致“落后者”拖慢整体进度，造成资源浪费或严重竞争。
*   **推理集群资源闲置：** 生产环境中的推理服务集群为应对突发流量通常过度配置，平均计算利用率仅约 18.9%，显存利用率约 14.3%。

**ROSE 的核心思想：** 提出“协作弹性（Cooperative Elasticity）”，即在保障推理服务质量（SLO）的前提下，动态“收割”推理集群中的空闲算力和显存，用于加速 RL 的 Rollout 过程。

#### 2. 方法论：核心思想与关键技术
ROSE 系统由三个关键组件构成：

*   **SLO 安全的共存执行器 (Co-serving Executor)：**
    *   **VMM 显存共享：** 利用 CUDA 虚拟内存管理（VMM）在异构模型（如推理用 7B，Rollout 用 32B）之间实现物理页面的快速重平衡，无需重启进程。
    *   **抢占式显存策略：** 优先保障推理服务的 KV Cache，在流量激增时强制回收 Rollout 的显存，并利用前缀缓存（Prefix Caching）提升多轮交互效率。
    *   **双 SLO 准入控制：** 实时监控推理服务的首字延迟（TTFT）和单字延迟（TPOT）余量，仅在不违背 SLO 的空隙插入 Rollout 计算任务。

*   **跨集群权重传输引擎 (Weight Transfer Engine)：**
    *   **稀疏性感知：** 发现 RL 训练中相邻步骤的权重增量（Delta）具有极高的稀疏性（>95%），通过 COO 格式压缩传输，大幅降低带宽压力。
    *   **分片与异步：** 支持训练与推理集群间不同的并行策略（TP/PP），通过中继层实现异步、容错的权重同步。

*   **弹性 Rollout 调度器 (Elastic Rollout Scheduler)：**
    *   **轮次级路由：** 不再将整个轨迹绑定在单一 GPU，而是按交互轮次动态分发。
    *   **缓存亲和性：** 优先将任务调度到持有该轨迹 KV Cache 的 GPU 上，减少重复计算。

#### 3. 实验设计
*   **数据集/场景：** 智能体任务 FrozenLake（使用 Qwen3-8B）和 ALFWorld（使用 Qwen3-32B）。
*   **算法：** GRPO 和 DAPO（一种支持冗余采样的算法）。
*   **基准方法 (Benchmarks)：**
    *   **资源固定类：** ROLL（同步 RL）、AReaL（异步 RL）。
    *   **资源弹性类：** RLBoost（利用抢占式 Spot 实例）、$\lambda$RL（基于 Serverless GPU）。
    *   **推理共存类：** Prism（通用 GPU 多任务系统）、ServerlessLLM。

#### 4. 资源与算力
*   **GPU 型号：** NVIDIA H800。
*   **算力规模：**
    *   **训练集群：** 16 至 48 个 GPU。
    *   **推理集群（被收割方）：** 16 至 64 个 GPU。
*   **网络：** 集群内 400 Gbps InfiniBand，跨集群 200 Gbps 以太网（实验中还测试了 1Gbps 到 200Gbps 的敏感度）。

#### 5. 实验数量与充分性
*   **实验规模：** 涵盖了从 8B 到 32B 不同规模的模型，以及 GRPO 和 DAPO 两种主流 RL 算法。
*   **消融实验：** 详细测试了显存抢占、前缀缓存、双 SLO 控制、权重稀疏化、调度策略等每个子组件的贡献。
*   **充分性评价：** 实验设计较为充分，不仅关注了 RL 的吞吐量提升，还严格监控了推理服务的 P99 延迟，证明了“协作”的安全性。对比了多种最新的弹性资源方案，具有较强的说服力。

#### 6. 主要结论与发现
*   **吞吐量提升：** 相比资源固定的基准，ROSE 将端到端平均吞吐量提升了 **1.20–3.31 倍**。
*   **SLO 保障：** 在收割资源的同时，推理服务的 P99 TTFT 和 TPOT 始终保持在预设的 SLO 阈值内。
*   **权重同步效率：** 稀疏性感知传输将 32B 模型的跨集群同步时间从数分钟降低至 **21 秒**。
*   **弹性优势：** 相比 Spot 实例，ROSE 避免了频繁的冷启动和模型加载开销（开销占比从 >7% 降至接近 0%）。

#### 7. 优点
*   **资源利用创新：** 首次提出在 RL 训练中利用生产推理集群的“协作弹性”，而非依赖昂贵的专用备用资源。
*   **技术融合度高：** 结合了 CUDA VMM、权重稀疏性、异步调度等多种底层优化技术。
*   **针对性强：** 深入分析了 Agentic RL 的多轮交互和长尾特征，提出的轮次级调度非常契合应用场景。

#### 8. 不足与局限
*   **组织架构依赖：** 该方案假设 RL 训练团队与推理服务团队属于同一组织且能共享基础设施，这在跨公司或公有云场景下可能存在管理和隐私障碍。
*   **模型配对限制：** 实验主要针对 Qwen 系列模型，虽然理论上支持异构，但如果 Rollout 模型与推理模型架构差异极大（如不同的算子实现），共存效率可能会下降。
*   **环境开销：** 论文主要优化了 GPU 端的计算，但未深入讨论大规模 Agent 交互时 CPU 端环境模拟（Environment Workers）可能带来的瓶颈。
