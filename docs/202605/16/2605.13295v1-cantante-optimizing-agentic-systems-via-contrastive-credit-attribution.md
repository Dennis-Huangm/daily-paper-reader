## 摘要
基于大语言模型（LLM）的多智能体系统在软件工程、预测建模和检索增强生成等复杂现实任务中表现出强大的性能。然而，自动化配置这些系统仍然是一个结构性挑战，因为评分仅在系统层面可用，而控制智能体行为的参数却是局部的。我们认为，优化这些系统本质上是一个信用分配问题。因此，我们提出了 CANTANTE，这是一个通过对比同一查询下多个联合配置的运行结果，将系统级奖励分解为每个智能体更新信号的框架。我们将其应用于提示词优化，将智能体提示词视为可学习的系统参数。我们在编程（MBPP）、数学推理（GSM8K）和多跳问答（HotpotQA）任务上，将 CANTANTE 与 GEPA 和 MIPROv2 进行了对比评估。在这些基准测试中，CANTANTE 在所有评估的优化器中获得了最佳平均排名，并始终优于未优化的提示词。与最强的基准模型相比，它在 MBPP 上提高了 18.9 个百分点，在 GSM8K 上提高了 12.5 个百分点，同时推理成本更低。在 HotpotQA 上，它的表现与最强基准模型保持在一个标准差范围内。至关重要的是，我们的信用相关性分析证实，归因器产生了有意义的单智能体信号，而非仅仅重复全局系统评分。

## Abstract
LLM-based multi-agent systems have demonstrated strong performance across complex real-world tasks, such as software engineering, predictive modeling, and retrieval-augmented generation. Yet automating their configuration remains a structural challenge, as scores are available only at the system level, whereas the parameters governing agent behavior are local. We argue that optimizing these systems is fundamentally a credit-assignment problem. We therefore introduce CANTANTE, a framework that decomposes system-level rewards into per-agent update signals by contrasting rollouts of multiple joint configurations on the same query. We instantiate it for prompt optimization, treating agent prompts as learnable system parameters. We evaluate CANTANTE against GEPA and MIPROv2 on programming (MBPP), mathematical reasoning (GSM8K), and multi-hop question answering (HotpotQA). Across these benchmarks, CANTANTE achieves the best average rank among all evaluated optimizers and consistently outperforms unoptimized prompts. It improves over the strongest baseline by +18.9 percentage points on MBPP and +12.5 percentage points on GSM8K, while incurring a lower inference cost. It remains within one standard deviation of the strongest baseline on HotpotQA. Crucially, our credit correlation analysis confirms that the attributer produces meaningful per-agent signals rather than echoing the global system score.

### 1. 核心问题与整体含义
*   **研究动机**：虽然基于大语言模型（LLM）的多智能体系统（MAS）在复杂任务中表现优异，但其配置（如提示词、角色分配）主要依赖人工调优。随着智能体数量增加，手动调优面临组合爆炸的困境。
*   **核心挑战**：**信用分配（Credit Assignment）难题**。系统反馈通常是全局性的（例如“任务是否成功”），而需要优化的参数是局部的（每个智能体的具体指令）。如何将全局奖励准确地分解并反馈给每个局部智能体，是自动化优化的关键瓶颈。
*   **整体含义**：本文提出了 **CANTANTE** 框架，旨在通过对比不同配置下的执行轨迹，将系统级奖励转化为智能体级别的更新信号，从而实现 MAS 的自动化、端到端优化。

### 2. 方法论：CANTANTE 框架
*   **核心思想**：引入**对比式组内归因（Contrastive In-Group Attribution）**。通过在同一个查询（Query）上运行多个不同的联合配置，利用 LLM 归因器对比它们在推理路径和结果上的差异，从而识别每个智能体对最终成败的贡献。
*   **关键技术细节**：
    1.  **提议（Suggest）**：每个智能体的局部优化器（如 CAPO）提出 $K$ 个候选参数（提示词）。
    2.  **执行（Rollout）**：将这些参数组合成 $K$ 个系统配置，在任务上运行，记录执行轨迹（Trace）和全局评分。
    3.  **对比归因（Attribute）**：将同一查询下的多条轨迹分组，由一个高能力的 LLM 归因器进行分析。归因器不仅看分数，还看中间步骤，为每个智能体分配 $[-1, +1]$ 范围内的标量信用分。
    4.  **更新（Update）**：局部优化器接收到归因后的信用信号，迭代优化各自的提示词。
*   **算法优势**：即使多个配置得分相同，归因器也能通过分析中间输出的质量（如推理逻辑是否严密、格式是否正确）来提供差异化的反馈信号。

### 3. 实验设计
*   **数据集与场景**：
    *   **MBPP（编程）**：测试条件循环结构（Planner-Executor-Validator）。
    *   **GSM8K（数学推理）**：测试并行集成结构（3个 Executor + 1个 Consensus）。
    *   **HotpotQA（多跳问答）**：测试检索增强生成（RAG）结构（Retriever-Reader-Synthesizer-Checker）。
*   **对比基准（Baselines）**：
    *   **GEPA**：基于反思的提示词进化方法。
    *   **MIPROv2**：基于贝叶斯优化的指令与示例优化器。
    *   **Initial**：由 GPT-OSS-120B 自动生成的初始提示词。
*   **模型配置**：下游任务智能体使用 **Qwen3-30B**，优化器和归因器使用 **GPT-OSS-120B**。

### 4. 资源与算力
*   **算力消耗**：实验在 **NVIDIA L40 GPU** 上运行。
*   **时长**：主实验耗时约 100 GPU 小时，消融实验耗时约 30 GPU 小时，**总计约 130 GPU 小时**。
*   **Token 预算**：每个优化任务严格限制在 1000 万个 Token 的预算内（包含所有智能体调用、优化器调用和归因调用）。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 3 个不同拓扑结构的基准测试，每个实验运行 3 个随机种子并报告标准差。
*   **消融实验**：非常充分。作者测试了：
    *   **归因组件**：对比了“身份归因”（直接传回全局分）与对比归因的效果。
    *   **鲁棒性**：更换了归因器的提示词、底层模型、局部优化器（如换成 EvoPrompt）。
    *   **超参数**：测试了不同对比组大小（$g$）和开发集样本量（从 300 减至 75）的影响。
*   **公平性**：所有方法在相同的 Token 预算下竞争，且对基准方法（MIPROv2）在某些失败案例中甚至给予了额外的预算以确保对比的客观性。

### 6. 主要结论与发现
*   **性能卓越**：CANTANTE 在所有评估中获得最佳平均排名。在 MBPP 上比最强基准提升 **18.9%**，在 GSM8K 上提升 **12.5%**。
*   **推理效率**：优化后的系统在 MBPP 和 GSM8K 上不仅更准，且**推理时的 Token 消耗更少**，证明了它能学到更简洁高效的指令。
*   **归因有效性**：信用相关性分析显示，归因器能准确识别关键智能体（如 MBPP 中的 Validator 是性能核心），而非简单地重复全局分数。
*   **低数据敏感度**：即使在极小的数据集（75个样本）上，CANTANTE 依然能保持强大的优化能力。

### 7. 优点
*   **解耦性强**：归因机制与具体的优化算法解耦，可以适配各种局部优化器。
*   **对比机制**：通过“组内对比”解决了 LLM 难以给出绝对评分的问题，使反馈信号更具区分度。
*   **诊断功能**：信用分配信号可以作为 MAS 拓扑设计的诊断工具，帮助开发者发现系统中的“冗余智能体”或“瓶颈智能体”。

### 8. 不足与局限
*   **拓扑固定**：该方法目前只优化智能体的参数（提示词），不涉及工作流拓扑结构（如增减智能体或改变连接方式）的动态优化。
*   **归因器依赖**：优化效果高度依赖于归因器 LLM 的能力。如果归因器弱于下游智能体，可能会产生误导信号。
*   **上下文限制**：随着智能体数量增加，执行轨迹会变长，可能超出归因器的上下文窗口或导致信息过载。
*   **额外开销**：引入归因步骤会消耗额外的优化预算（Token），在极度受限的预算下可能存在权衡。
