## 摘要
基于可验证奖励的强化学习（RLVR）显著提升了大语言模型（LLM）的推理能力，特别是在涉及工具使用等环境交互的多轮智能体场景中。然而，由于极高的计算需求，微调此类模型仍然昂贵得令人望而却步，限制了其普及性。我们提出了 MARLaaS（多租户异步强化学习即服务），这是一个支持跨多个用户和任务进行并发强化学习微调的系统。我们的方法基于两个核心思想：（1）通过轻量级 LoRA 适配器在租户间共享基础模型；（2）采用解耦的异步架构，将 rollout 生成、环境交互和策略训练分解为独立调度的阶段。这种设计使任务能够以事件驱动的方式按照各自的节奏在强化学习流水线中推进，从而减少了跨任务干扰、空闲时间以及端到端延迟。在多任务设置下（我们报告了多达 32 个并发任务），MARLaaS 在达到单任务最先进性能的同时，将加速器利用率提高了多达 4.3 倍，并将端到端训练时间缩短了 85%。

## Abstract
Reinforcement Learning from Verifiable Rewards (RLVR) has significantly improved the reasoning capabilities of large language models (LLMs), particularly in multi-turn agentic settings involving environment interaction like tool use. However, fine-tuning such models remains prohibitively expensive due to high computational requirements, limiting accessibility. We propose MARLaaS (Multi-tenant Asynchronous RL as a Service), a system for concurrent RL fine-tuning across multiple users and tasks. Our approach is based on two key ideas: (1) sharing a base model across tenants using lightweight LoRA adapters, and (2) a disaggregated asynchronous architecture that decouples rollout generation, environment interaction, and policy training into independently scheduled stages. This design enables tasks to progress through the RL pipeline at their own pace in an event-driven manner, reducing cross-task interference, idle time, and end-to-end latency. In multi-task settings (we report up to 32 concurrent tasks), MARLaaS achieves single-task state-of-the-art performance while improving accelerator utilization by up to 4.3x and reducing end-to-end training time by 85%.

### 1. 核心问题与研究动机
*   **核心问题**：大语言模型（LLM）的强化学习微调（RLVR，如 DeepSeek-R1 采用的技术）虽然能显著提升推理和智能体能力，但**计算成本极高且资源利用率低下**。
*   **研究背景**：
    *   **阶段性空闲**：传统的 RLVR 训练包含 Rollout（生成）、环境交互（如工具调用）和策略训练三个阶段。这些阶段通常顺序执行，导致生成时训练算力闲置，环境交互（等待 API 响应）时加速器完全空闲。
    *   **多租户扩展难**：为每个用户/任务独立部署模型会消耗海量显存，难以在共享硬件上支持多任务并发。
*   **整体含义**：提出一种“强化学习即服务”（RL-TaaS）架构，通过异步解耦和多租户共享技术，降低 RL 微调的门槛和成本。

### 2. 方法论
MARLaaS 的核心思想是**“空间共享+时间重叠”**：
*   **轻量级多租户共享（Multi-LoRA）**：
    *   所有租户共享一个冻结的基础模型（Base Model）。
    *   每个任务仅维护独立的 LoRA 适配器和优化器状态，极大地降低了显存占用，允许在同一组 GPU 上并发运行数十个任务。
*   **解耦的异步架构（Disaggregated Asynchronous Architecture）**：
    *   **组件解耦**：系统分为多任务管理器（M）、Rollout 引擎和训练引擎。
    *   **事件驱动调度**：任务不再需要全局同步。当一个任务在进行环境交互时，Rollout 引擎可以为另一个任务生成数据，训练引擎则可以更新第三个任务的参数。
    *   **版本一致性保证**：虽然是异步的，但系统确保每个任务仅使用其最新提交的策略版本生成的轨迹进行训练，避免了“策略陈旧（Staleness）”导致的收敛问题。
*   **非对称设计**：针对 RLVR 中 Rollout 耗时远大于训练（10-100倍）的特点，系统支持跨任务的 Multi-LoRA 批量生成以最大化吞吐量，而训练则按需顺序执行。

### 3. 实验设计
*   **数据集与场景**：
    *   **GSM8K**：小学数学推理。
    *   **AMC12**：竞赛级数学，推理链更长。
    *   **Agentic Search**：智能体搜索任务（基于 HotpotQA），涉及 Wikipedia API 调用，具有高延迟的环境交互。
*   **基准模型**：Qwen3-0.6B、14B 和 32B。
*   **对比方法（Baselines）**：
    *   **Single-Disaggregated**：单任务独占资源，顺序执行。
    *   **Single-Collocated**：单任务在共享池中执行（理想化的紧耦合上限）。
    *   **Multi-LoRA (Sync)**：多任务共享资源但强制全局同步。

*   **硬件环境**：使用两个节点的 **Ascend（昇腾）集群**，每个节点配备 16 个 NPU（共 32 个 NPU，每个 64GB 显存）。
*   **软件框架**：基于 AReaL 系统和适配昇腾的 vLLM 构建，使用 FSDP（全分片数据并行）进行训练。
*   **算力分配**：
    *   0.6B 模型：2 个 NPU 用于训练，其余用于 Rollout。
    *   14B 模型：4 个 NPU 用于训练。
    *   32B 模型：16 个 NPU 用于训练。

### 5. 实验数量与充分性
*   **实验规模**：报告了多达 **32 个并发任务**的扩展性实验。
*   **消融实验**：专门对比了“无异步”和“无 Multi-LoRA”的情况，验证了各组件的贡献。
*   **充分性评价**：实验覆盖了从轻量级（0.6B）到中大规模（32B）的模型，且涵盖了纯推理和复杂智能体交互场景。通过 10 个副本的并发测试证明了系统在处理异构负载（不同任务进度不一）时的鲁棒性，实验设计较为客观、公平。

### 6. 主要结论与发现
*   **效率提升**：相比单任务基准，MARLaaS 将加速器利用率提升了 **4.3 倍**，总吞吐量提升了 **5.7 倍**。
*   **时间缩减**：在达到相同奖励水平的前提下，端到端训练时间减少了 **85%**。
*   **扩展性**：系统能有效处理多租户带来的“长尾效应”，即使在 32 个并发任务下，依然能保持较低的作业调度延迟（TTFS）。
*   **性能保持**：异步调度并未损害模型的收敛质量，奖励曲线与单任务同步训练保持一致。

### 7. 优点与亮点
*   **解决痛点**：精准捕捉到了 RLVR 任务中“Rollout 绑定”的非对称性，通过异步化消除了流水线气泡。
*   **低成本扩展**：利用 LoRA 适配器实现了极高的任务密度，使得在有限硬件上开展大规模 RL 实验成为可能。
*   **用户友好**：显著降低了任务提交后的等待时间（TTFS），提升了云端服务的响应速度。

### 8. 不足与局限
*   **训练瓶颈**：目前设计中训练引擎是单任务顺序执行的，当并发任务极多且模型极大时，训练阶段可能成为新的瓶颈。
*   **显存限制**：尽管使用了 LoRA，但 KV 缓存（KV-Cache）在处理超长上下文或极高并发时仍是物理上限。
*   **调度策略简单**：目前采用 FIFO（先来先服务）调度，缺乏针对任务优先级或动态资源调整的复杂策略。
*   **硬件依赖**：实验主要在昇腾架构上完成，虽然理论通用，但在其他硬件（如 NVIDIA GPU）上的表现及适配工作未详细展开。
