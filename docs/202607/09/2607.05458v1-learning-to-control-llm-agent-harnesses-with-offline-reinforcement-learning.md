## 摘要
大语言模型（LLM）智能体通常通过更改提示词、模型或手写工作流来改进，而模型周围的执行框架（harness）则被视为固定的基础设施。我们认为，这种执行框架本身就是一个可学习的控制层。我们将执行框架的操作形式化为一个有限时界的执行框架马尔可夫决策过程（Harness MDP），其中轻量级控制器选择结构化执行动作，而 LLM 执行器保持冻结。该控制器利用离线展开数据，通过优势加权回归进行训练，且仅使用终端任务准则奖励。我们还将最终任务质量与事后执行框架成熟度评分（Harness Maturity Score）分开，后者衡量执行框架是否遵循可靠的执行模式，而不仅仅是最终答案是否正确。这种分离提供了一个执行框架学习的有限缓冲区视角：最终质量的提升需要离线缓冲区中高回报的支持，而过程行为只要与优势加权动作一致即可发生转变。在六个受控领域和两个公共基准适配器上，学习到的控制器一致地改善了验证行为，并选择性地提高了最终任务质量，在适配的 tau-bench retail、适配的 AgentBench DB-Bench 以及带有校准结构化验证器的编程任务中增益最大。针对行为克隆和强制检查（Forced CHECK）的消融实验表明，这些增益不能通过模仿或简单地添加检查来解释。这些结果表明执行框架控制是冻结 LLM 智能体的一个可学习层，同时也展示了离线支持限制了更好的过程控制何时能转化为更好的最终答案。

## Abstract
Large language model (LLM) agents are usually improved by changing prompts, models, or hand-written workflows, while the execution harness around the model is treated as fixed infrastructure. We argue that this harness is itself a learnable control layer. We formalize harness operation as a finite-horizon Harness MDP, where a lightweight controller selects structural execution actions while the LLM executor remains frozen. The controller is trained from offline rollouts using advantage-weighted regression with only terminal task-rubric rewards. We also separate final task quality from a post-hoc Harness Maturity Score, which measures whether the harness follows reliable execution patterns rather than only whether the final answer is correct. This separation gives a finite-buffer view of harness learning: final-quality gains require high-return support in the offline buffer, while process behavior can shift whenever it aligns with advantage-weighted actions. Across six controlled domains and two public-benchmark adapters, the learned controller consistently improves verification behavior and selectively improves final task quality, with the largest gains on adapted tau-bench retail, adapted AgentBench DB-Bench, and coding with a calibrated structural verifier. Ablations against behavior cloning and Forced CHECK show that the gains are not explained by imitation or by simply adding checks. These results identify harness control as a learnable layer for frozen LLM agents, while showing that offline support limits when better process control becomes better final answers.

### 1. 核心问题与整体含义（研究动机和背景）
传统的 LLM 智能体优化通常集中在提示词（Prompts）、模型微调或预定义的工作流上，而其周围的**执行框架（Harness）**——即决定何时调用工具、何时检索、何时检查或提交的控制逻辑——通常被视为固定的基础设施。
论文指出，这种固定的框架（如“总是检查”或“草稿后立即提交”）在处理不同难度的任务时缺乏灵活性。研究者提出将执行框架视为一个**可学习的控制层**，通过离线强化学习（Offline RL）让智能体自主学习在不同状态下采取最佳的执行动作，从而在不改变 LLM 本身的情况下提升性能。

### 2. 方法论
*   **Harness MDP 形式化**：将框架操作定义为有限时界的马尔可夫决策过程。
    *   **状态（State）**：包含轨迹进度、草稿状态、证据覆盖率、工具输出、验证器反馈、剩余预算等特征。
    *   **动作空间（Actions）**：定义了 7 种结构化动作：`OBSERVE`（观察）、`RETRIEVE`（检索）、`CALL-TOOL`（调用工具）、`DRAFT`（起草）、`CHECK`（检查）、`REVISE`（修改）和 `SUBMIT`（提交）。
*   **核心算法：优势加权回归（AW）**：
    *   使用离线展开缓冲区（Offline Rollout Buffer）进行训练。
    *   **训练机制**：采用加权行为克隆（Weighted Behavior Cloning）。对于缓冲区中的每个状态-动作对，根据该轨迹获得的终端奖励（相对于平均水平的优势）赋予权重。高回报轨迹中的动作会被赋予更高权重，从而增加控制器在未来选择这些动作的概率。
*   **过程与结果分离**：
    *   **终端任务奖励 ($Q$)**：基于任务准则（Rubric）的最终得分。
    *   **执行框架成熟度评分 (HMS)**：一种事后诊断指标，衡量智能体是否遵循了良好的过程行为（如提交前先检查、失败后修改等），但不直接用于训练。

### 3. 实验设计
*   **实验场景**：
    *   **6 个受控领域**：知识工作（KW）、编程（Coding）、研究问答（Research）、多工具使用（Multi-tool）、长记忆（Long-memory）、规划（Planning）。
    *   **2 个公共基准适配器**：$\tau$-bench retail（策略约束工具交互）和 AgentBench DB-Bench（数据库推理）。
*   **对比方法（Baselines）**：
    *   **Base**：原始固定框架。
    *   **Behavior Cloning (BC)**：纯行为克隆，不考虑奖励优势。
    *   **Forced CHECK (FC)**：机械式地在提交前插入检查步骤，用于验证增益是否仅来自“多做检查”。
*   **评估协议**：每个领域 100 个任务（80 训练/20 测试），采用 3 个独立随机种子，每个测试任务进行 3 次展开。

### 4. 资源与算力
*   **控制器架构**：非常轻量级，仅为一个具有 64 个隐藏单元的单隐藏层 MLP。
*   **训练细节**：使用 Adam 优化器，学习率 $10^{-3}$，Batch Size 256，训练 20 个 Epoch。
*   **算力说明**：论文**未明确说明**具体的 GPU 型号、数量或总训练时长。但由于控制器极小且 LLM 处于冻结状态，可以推断其训练算力需求远低于模型微调。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 8 个不同的领域/基准，总计进行了数千次轨迹展开。
*   **充分性**：实验设计较为全面，包含了消融实验（对比 BC 和 FC）以及针对验证器校准和阈值敏感性的分析。
*   **客观性**：通过引入“缓冲区松弛度（Buffer Slack）”理论分析，客观地解释了为什么某些领域性能提升有限（受限于离线数据中高回报轨迹的缺失），而非盲目宣称方法万能。

### 6. 主要结论与发现
*   **过程行为的一致改进**：AW 控制器在所有设置中都显著增加了“提交前检查”（CheckBeforeSubmit）的行为，HMS 评分在大多数领域均有提升。
*   **最终质量的选择性提升**：最终任务得分 ($Q$) 的提升在不同领域表现不一。在编程、$\tau$-bench 和 DB-Bench 中增益显著，但在某些受控领域增益较小。
*   **离线支持的限制**：实验证明，只有当离线缓冲区中存在能够将“更好的控制决策”转化为“更好结果”的高回报轨迹时，最终质量才会提升。
*   **优于基准**：AW 在多数情况下优于 BC 和机械式的 FC，证明了**状态相关（State-conditioned）**的控制逻辑比简单的模仿或固定规则更有效。

### 7. 优点
*   **视角新颖**：将智能体框架视为可学习的控制层，为冻结 LLM 的性能优化提供了新路径。
*   **理论支撑**：提供了关于奖励设计不变性和有限缓冲区支持的理论证明。
*   **轻量高效**：无需微调大模型，仅通过训练微型控制器即可改变智能体行为。
*   **诊断深入**：通过 HMS 指标深入分析了智能体“做事过程”的改进，而非仅关注最终分数。

### 8. 不足与局限
*   **依赖离线数据质量**：如果离线缓冲区中没有高质量的成功轨迹，控制器无法凭空“发明”出提升结果的策略。
*   **领域泛化限制**：虽然动作空间通用，但每个领域仍需要特定的适配器和状态向量设计。
*   **过程与结果的脱节**：在某些领域（如研究问答），虽然过程变得更“成熟”了，但最终得分并未随之提高，甚至出现了因“过早提交”导致的负面影响。
*   **验证器依赖**：实验结果对验证器（Verifier）的校准非常敏感，不同的评分准则会显著影响测得的增益。
